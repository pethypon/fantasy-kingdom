**履歴について**：この調査は通常攻撃1回の条件で実行した記録です。後続変更で現行の標準上限は2回となりました。詳しくは [通常攻撃2回](../../Rules/2026-11-03-通常攻撃2回.md) を参照してください。

## 今回の変更

- 観測済みの相手メインクリスタルの攻略作戦を、損耗・時間切れ・補充待ちで捨てないようにした。同じ優先層では通常の攻勢より本拠点攻略を優先し、緊急防衛や経済危機では中断・再開する。標準の4駒部隊は維持する。
- 本拠点を実際に再確認したら、周辺防衛の全マス視認を待たず集結・接近へ進むようにした。未確認の防衛は安全と断定せず、必要戦力への不確実性加算や行動ごとの合法性確認を残す。
- 記憶した本拠点が視界外でも、既知の通行可能地形から再観測点を探す。見晴らし地点を見たことと本拠点を実際に見たことを区別する。無成果の偵察地点は一定期間避ける。見えている本拠点を最後の健康な斥候が不用意に見失わないようにした。
- 実際に合法な本拠点への通常攻撃が候補にある場合、緊急行動を除き1回分のAP機会を先に確保する。隠れた本拠点への攻撃は生成しない。敵領土・記憶した本拠点へ進む斥候にも安全な進捗行動を自軍ターンに1回優先する。
- 自軍の戦闘による死亡地点と、実際に見えている強敵の脅威を記憶する。繰り返し損耗した場所には別経路を要求し、退却・危険からの離脱は妨げない。安全な再調査または時間経過で危険度を解消する。維持費不足や自傷を戦死として学習しない。
- 敵領土をまだ発見していない場合も、探索済み領域の偏りから未確認方向を推定する。16区画による探索順位であり、敵本拠点の真の座標や統計的に較正された存在確率ではない。
- 既知の本拠点・敵領土・発見済みダンジョン・視認中の強敵への接近、補給接続、脱出方向、危険記憶をサブクリスタル候補の採点へ統合した。最後の1個は具体的な攻略・確保の目的がある地点に残す。設置条件や費用は緩和していない。
- 通常攻撃に既にあった疲労加算は重複追加せず、実AP処理とAI見積りの一致を検証し、ヘルプに記載した。
- 召喚上限は各陣営の自軍ターンに合計1体。兵種・メイン／サブ拠点で共有する。召喚直後の攻撃禁止は維持する。
- 通常攻撃は駒1体につき自軍ターンに1回。能動スキル・自動反撃・反射は別枠。実攻撃処理、AP判定、UI、AI候補、先読み、盤面ハッシュ、コピー、セーブ／ロードへ統合した。相手の次ターンの危険予測では、その相手が前のターンに攻撃済みであることを理由に脅威を消さない。
- メインクリスタルは初期HP1000・上限2000、サブクリスタルはHP500。欠片の最大HP増加は1000、上限分は最大30魔石へ変換する。上限に達した欠片で無料回復させず、死亡済みクリスタルを復活させない。旧セーブは残りHP割合と死亡状態を保ち、旧基礎HPから得た増加分を新上限内で引き継ぐ。
- 開発スタジオに「全設定」を追加。ゲーム用のScriptableObjectを自動収集し、分類・検索・項目編集・保存・Undoに対応する。シーン／Prefab部品・マテリアルへの編集導線とUnity詳細設定への導線も追加した。全設定の対象と制約は [編集ガイド](../../DevelopmentStudio/全設定の編集.md) を参照。
- 共通戦闘・召喚・クリスタルの値を `GameplayTuning.asset` に設定化し、プレイヤー・敵AI・先読みが同じ値を使う。設定変更後に召喚上限を下げても旧セーブの消費済み枠から追加召喚できない。IDを編集して既存セーブの参照を壊さないように、駒・建物の保存用IDは読み取り専用にした。

### 問題の記録

**修正済み：本拠点の偵察段階が終わらない。** 証拠は `attack_quota_trial` の作戦表と制御テスト。部分的な視界で本拠点だけを観測し、即時攻撃できる駒を置かずに攻略作戦を更新すると、従来は防衛半径の全マス視認条件で止まった。以前の試作2ケースで、敵AIは本拠点を記憶しながら段階0のままだった。実視認した本拠点の再確認で次段階へ進めるよう修正した。副作用として不明な防衛へ接近する可能性があるため、未知防衛の戦力見積り、経路確認、行動時の合法性確認、緊急中断は維持している。

**未解決：本拠点への攻撃を継続できない。** 最新シード271828で実攻撃は3回、51ラウンド目が最後。作戦自体は120ラウンドまで継続している。少数の先行駒と主力の到着・補充・回復の同期が不十分な可能性があるが、直接の原因は未確定。改善案は、部隊単位の到達率と損耗、攻城位置の維持、交代要員と回復役の到着をログで分け、局所の防衛・退却と集団進軍の優先度を確認すること。突撃だけを強制すると損耗を増やす副作用がある。

**未解決：敵領土発見後も本拠点発見へ至らない試合。** 最新シード314159では両陣営が敵領土を把握したが、本拠点は120ラウンドまで未視認。最新2試合中1試合で確認。既知地形の連結性、危険回避、斥候の目標到達、視界獲得のどこで停滞したかはさらに切り分けが必要。未発見座標を教える対策は採用しない。

**未解決：移動先占有による実行失敗。** 最新試合の失敗回数はPlayer11／21、Enemy2／28。ログの多くは `move_destination_occupied`。候補作成と実行の間の混雑、未視認の占有などが考えられるが、全件同じ原因とは断定しない。既知の味方占有・部隊間予約を切り分けるのが改善案で、視界外の占有を不正取得して候補から消すことはしない。失敗をゲームの例外と混同しない。

**UI：密集時のHP／バリア。** `final-314159-round120.png` で上部右側の複数ゲージが重なる。単一の120ラウンド画像で確認し、全解像度での発生率は未検証。選択・ホバーを優先して展開し、通常時は詳細数値の表示密度を落とす設定が候補。ただし情報を隠しすぎる副作用があり、今回はHP表示の新仕様へ勝手に変更していない。

主要変更は `Operation/AIOperationManager*.cs`、`EnemyTerritoryIntel*.cs`、`Exploration/AIExplorationPlanner*.cs`、`AICommander.APBudget.cs`、`AIOutpostPlanner.cs`、`MainCrystalRules.cs`、`NormalAttackTurnRules.cs`、`SummonTurnRules.cs`、`Status.cs`、セーブ／AIシミュレーション／UIの接続部、`GameplayTuning.cs` と開発スタジオの部分クラス。制御テストは `Tests~/AICampaignContracts.cs`、`AIRouteStrategyContracts.cs`、`NormalAttackTurnTests.cs`、`StudioAllSettingsTests.cs` 等にある。

## 残る制約

危険経路の回避は保守的な推定であり、唯一の狭路では安全確認や危険度の減衰まで待機する可能性がある。サブクリスタルの方針は目的に合う合法候補を採点するもので、全試合で必ず攻略拠点を建てる保証ではない。斥候の観測予測は既知地形と行動範囲を使うが、全ての視界バフ／地形効果の組合せを網羅検証していない。

危険地点128件、死亡ID256件、偵察再試行128件、地形仮説16区画、拠点の補給調査2048セルに上限を設けた。これは履歴の無制限増加を防ぐ対策であり、長時間プレイのCPU/GPU負荷が改善したという実測結果ではない。

全18職種・全難易度・全環境の総当たりバランス、長時間のメモリ傾向、すべてのUI解像度は未検証。新しい全設定画面がコード内の全定数や新ゲームロジックまで編集できる、とも主張しない。
