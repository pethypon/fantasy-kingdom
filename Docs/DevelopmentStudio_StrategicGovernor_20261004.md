# 開発スタジオとAI戦略統括

Unityの上部メニュー **Fantasy Kingdom → 開発スタジオ（日本語）** を開きます。ゲームを停止して編集し、右上の「すべて保存」を押してください。駒・建物・ルールは通常のUnityアセットとして保存します。

## 駒づくり

1. 「＋ 新しい駒」または「選択した設定を複製」を押します。
2. 表示名、種類の分類、初期陣営、基礎役割、HP・攻撃・防御、成長率、作成費・維持費を設定します。
3. 「行動タイプの名前」と行動の組み合わせを設定します。行動タイプは独立した `BoardActionProfile` アセットなので、複数の駒で共有できます。
4. 移動・攻撃・視界の **8×8マス** をクリック／ドラッグで設定します。黄色が駒の現在地、青が移動、赤が通常攻撃、緑が視界です。画面幅が狭い場合はタブで切り替えます。
5. 使いたいモデルを指定し、専用Prefabを生成できます。基本形だけでもゲーム内で選択・召喚できます。

「この駒専用のマス設定を使う」をOFFにすると、その基礎役割の既存ルールを使います。ONにすると選択したマスを使い、方向依存の配置は駒の向きに合わせて反転します。自分のマスは移動先・攻撃先にできません。視界には自分のマスを含めます。

基礎役割は既存AIの評価や特殊処理との接続に使います。同じ役割でも、保存用ID・名前・能力・Prefab・マス配置が違う駒を追加できます。「種類の分類」は自由入力です。特殊能力とスキルの効果は既存の実装から選択します。8×8の攻撃マスは**通常攻撃**で、スキル固有の範囲とは別です。

プレイヤーの召喚、敵AIの召喚、セーブ・ロード、視界、移動候補、攻撃候補、戦闘シミュレーションは、その駒の個別データを参照します。複製では別の保存用IDとマス設定・Prefabを生成し、元の駒を上書きしません。

## 建物づくり

既存の建物18種類を、建築費・AP・レベル別能力・生産・強化費用つきの編集用データとして追加しています。「既存の建物データを取り込む」で不足分を再作成できます。既にある編集用データは上書きしません。

編集用の複製は、一覧に表示するだけでは建築メニューに重複追加されません。必要な建物を複製し、「この建物をゲームに登録」でゲーム内に追加してください。新しい建物を作成した場合は登録済みです。

建物ごとに、基本動作、建築費、レベル別HP・攻撃・防御、材料の投入量、生産量、確率生産、維持費、強化費用を編集できます。住宅の人口枠や倉庫の容量などは、対応する基本動作と特殊効果の値で設定します。**移動・攻撃・視界の8×8エディタは駒用です。** 建物のUIには置いていません。

建築・強化・生産・維持・セーブ・ロードは、同じ基本動作の建物が複数あっても、個別の保存用IDで識別します。

## 資源・行動ポイント・ゲーム設定

「陣営・ゲームルール」タブで設定します。

| 設定場所 | 変更できる内容 |
| --- | --- |
| 時間とAP | ターン時間、各軍の持ち時間、手動ターン終了時の加算秒数、AP上限、基本移動・攻撃AP、高さ差の追加AP、市民によるAP増加 |
| 維持・経済 | 市民のパン消費、飢餓の猶予ターン数、AIのパン予備ターン数 |
| 陣営の初期状態 | 各陣営の名前・表示色・初期AP、プレイヤー／敵軍の木材・石材・鉄・魔石・小麦・パン・水・市民の初期量 |
| 新規マップ | 幅・奥行き、地形の細かさ、川の半幅 |
| 駒／建物の個別設定 | 作成・建築・強化の資材とAP、維持費、施設の生産量・投入量 |

「このルールで新規ゲームを始める」をONにして保存すると使われます。初期状態を設定する項目は新規ゲームで適用し、ロード時は保存した状態を復元します。消費AP・AP上限・市民の消費などの共通ルールは、ロードしたゲームにも適用します。AP上限は既存エンジンの範囲内（3～50）で変更できます。毎ターンの回復量は初期AP＋市民ボーナス－ペナルティを、この上限までに制限します。

設定アセットを無効にした場合は従来のゲームルールを使います。第三陣営は通常の経済資材を使わず、強敵は駒ごとの専用APを使います。陣営の操作方式・ターン順はゲームシステムに従います。

## 第三陣営

「第三陣営のイベント」タブで、ダンジョン襲撃・領土襲撃・強敵の領土拡大を設定できます。襲撃には「駒づくり」の駒を選べます。IP費用、発生する脅威度、待機ターン数、対象陣営、駒数、出現したターンから行動するか、処理上限も調整できます。

ターン順は **プレイヤー → 敵軍 → 第三陣営 → 強敵** です。介入判断のIPと、出現した駒が使うAPは別です。診断画面は **Fantasy Kingdom → 第三陣営 → 判断状況を確認** から開きます。

## AI Strategic Governor

既存の戦闘・建築スコアの上に、安全条件と優先段階を追加しました。

- **P0**：Kingの既知の致死危険を避ける。安全な代替がある場合は危険な候補を採点前に除外し、全部が危険な場合は最も被害の少ない候補を残します。危険を除去できるKingの攻撃は許可します。
- **P1**：観測した敵の攻撃・次の移動からの脅威に対して、限られた防衛役を割り当てます。防衛役の追撃とサブクリスタル拡張を制限します。
- **P2**：自軍の施設レシピ・投入材料・維持費・市民食料・既存駒の維持を使って経済を予測します。資材が0未満にならなくても支払失敗を記録し、維持不能な召喚を禁止します。食料や不足する投入材料の生産を優先します。
- **P3**：専任の探索役で長距離の目標を保持します。Kingは探索・前衛の役割に割り当てません。緊急防衛・経済回復時は目標と既存作戦を一時停止し、解除後に再開します。
- **P4**：同じ優先段階で従来の戦術評価・先読み・性格・学習を使います。

候補の並び順、最終選択、代替行動、実行直前で安全条件を維持します。目標はセーブに保持し、Unityの一時的なインスタンスIDを保存しません。不可視の敵の実座標を新たに取得して安全判定する処理は追加していません。

追加した建物／駒の建築・召喚候補は個別の費用と経済予測で評価します。新規レシピの建築・召喚は従来のMinimax生産モデルでは正確に再現できないため、その候補を古いレシピに置き換えてシミュレーションしません。配置済みの個別駒の移動・通常攻撃・視界設定はシミュレーションに反映します。

添付された仕様書は「25. パン工房をハードコードしない」の途中で終わっています。本実装は受領できた本文と冒頭の要件を対象にしています。

## 保存先とコード

- `Assets/_FantasyKingdom/GameContent/Units`：新しく作成した駒
- `Assets/_FantasyKingdom/GameContent/Buildings`：新しい建物と既存の編集用データ
- `Assets/Resources/GameContent/Rules.asset`：資源・AP・ゲームルール
- `Assets/Resources/GameContent/UnitCatalog.asset`、`FacilityCatalog.asset`：ゲームへ追加登録したデータ
- `Assets/Resources/AI/ThirdFaction`：第三陣営の設定
- `Assets/Editor/GameDevelopmentStudioWindow*.cs`、`DevelopmentStudioTiles.cs`：日本語編集画面
- `Assets/Script/Unit&Battle/BoardActionProfile.cs`：8×8マスのデータと判定
- `Assets/Script/Gamesystem/TurnSystem/Enemy/AIStrategicGovernor.cs`、`StrategicEconomyForecast.cs`：AIの優先段階・安全条件・経済予測

既存データのIDやアセットを削除すると、それを参照するセーブを復元できなくなります。公開後はIDを維持し、変更したいデータを複製して追加する運用ができます。
