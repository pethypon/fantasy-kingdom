# 時間切れ・制作ツール・寿命管理

## 修正対象

- PlayerMove のターン終了を一度限りとし、終了したステートで入力処理を続行しない。
- EnemyMove もターン・総持ち時間切れを購読し、終了時に解除。AI反復の境界で終了し、途中のIEnumeratorを破棄する。
- TimerSystem は残時間を0未満にせず、不正な保存値・NaNの経過時間を処理。満了を通知する前に停止する。
- 終了済みのゲームを別のステートで上書きしない。nullステートを拒否。
- 実機ログで繰り返していた FloatingDamageUI のNullReferenceを修正。再コンパイル後のプール再構築で既存オブジェクトを再利用。表示がない間はUpdateを停止。
- UnitSetting が作ったフォールバック用ScriptableObjectだけを解放。プロジェクトのアセットは破棄しない。

## 制作と互換性

ユニット工房で既存行動タイプの見た目・能力値・成長・コストを設定できる。作成Prefabは既存データと別の一意なフォルダへ保存。登録カタログは任意で、未登録・不正な設定は従来の設定にフォールバックする。
Kindの列挙値とセーブ形式は変更しない。既存セーブの能力値は復元処理を優先し、外見はそのタイプの有効なPrefabを用いる。
新しい行動タイプを無制限に増やす仕組みではない。新ルールの追加は移動・攻撃・AI・保存互換性を一緒に検証する。

既存の外部アセット・Resourcesを一括移動せず、プロジェクト案内で用途別に辿れるようにする。新規ユニットは `_FantasyKingdom/Units` に集約する。

## 継続検証

`Tests~/LongevityTests.cs` は検証用Editor環境で実行する。時間切れ（移動・攻撃・建築・敵ターン）、二重終了、総時間切れ、破損した時間値、ダメージプール復旧、Prefab生成・登録・実行時能力値適用、不正コスト拒否を検証する。
既存の SceneSmoke 検証も併用する。テストは分離したUnityValidationプロジェクトで実施し、テスト用アセットと会社名・製品名を製品ビルドに残さない。

将来の変更でも不具合ゼロを保証するものではない。今回の再現ケースと回帰検証を、Unity更新・ルール追加時にも繰り返せる状態にする。

検証結果: 統合454項目（追加21項目）通過。Windows版は Builds/Windows-20260929-Maintenance に出力し、ヘッドレス起動ログを確認。ビルド終了時にUnity内部のJobTempAlloc警告が出たため、ゲーム全体のメモリリークがないという保証やFPS向上率の主張は行わない。
