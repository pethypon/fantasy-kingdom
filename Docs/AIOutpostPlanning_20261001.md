# 探索・前線拠点・ダンジョン確保

## 行動

- 既存の探索 → 拠点候補比較 → 増援 → 戦闘判断の順に、盤面更新を反映する。
- 発見済みの未確保ダンジョンへ偵察駒を誘導する。視界から外れても発見済みの位置は使うが、隠れた支配状態・報酬状態は読まない。
- ダンジョン本体または周囲1マスの合法な位置にサブクリスタルを置き、占有できる候補を優先する。
- 通常の前線拠点は、経済施設が最低2棟あることを条件に、敵の接触位置／未探索方向、既存拠点からの距離、味方の支援、視認敵の近さを比較する。
- 既存拠点から4～14マス、支援する味方から6マス以内を基準にする。敵が2マス以内なら見送り、5マス以内も減点する。これは軽い距離評価であり、経路到達可能性や将来の敵移動を完全に保証するものではない。
- 1ターンの設置は最大1個。設置済みフラグは同じターンの盤面更新でも維持し、古い師団提案の重複実行も拒否する。
- 設置には既存の視界・領土・資源・AP・在庫ルールを適用する。確保済みダンジョンへの偵察誘導は解除する。

## 軽量化

従来はマップ列挙順の最初の5個から2候補を作っていた。これを現在の視界内だけの列挙＋既存の高さインデックスへ変更した。全合法位置を評価して上位4個だけ後続処理に渡す。候補は4要素の挿入比較で選び、全候補のソートを行わない。

候補スコア、味方拠点、未確保の既知ダンジョン、現在視認中のダンジョン一覧は盤面世代単位で再利用する。新しい世代や DungeonSystem の差し替え時に更新する。

計測: 合法位置693個の評価後、キャッシュ済み候補・スコア・視認ダンジョンを各1万回参照して約0.748ms、追加マネージド確保0バイト。これは該当参照処理の測定であり、ゲーム全体のCPU/GPU負荷や最適化の限界を証明するものではない。

## 検証

Unityの分離コピーで回帰テスト619項目通過。うち新規15項目は候補の取りこぼし防止、未発見ダンジョンの秘匿、候補順位の列挙順非依存、安全性、実際の設置・占有、1ターン1個、確保済み目標の解除、キャッシュの無割り当てを含む。

最初の実行では既存Minimaxスライスの性能テストが約438msを記録して失敗した。再実行以降の全体テストは通過したが、フレーム時間のばらつきがあるため「限界まで軽量化済み」とは判断しない。

## 編集箇所

- `Assets/Script/Gamesystem/TurnSystem/Enemy/AIOutpostPlanner.cs`: 拠点選定、支援距離、危険度、既知ダンジョン
- `AIActionGenerator.cs`: 上位候補、支払い・設置数の条件
- `AICommander.cs`: 探索後の設置判断
- `AIReconnaissance.cs`: ダンジョンへ向かう偵察評価
- `AIBoardState.cs`, `AIBoardState.Recon.cs`: 視界内の候補生成、キャッシュと設置済み状態
- `AIActionExecutor.cs`: 重複設置防止。開発ログ `[AIOutpost]` に設置理由を記録する。

テスト: `Tests~/OutpostPlanningTests.cs`。既存セーブ形式の変更はなし。拠点候補は現在の視界・探索情報・味方拠点から再計算する。
