# 地形・軽量化 R1 実装報告

対象: Unity 6000.3.8f1 / Fantasy Kingdom。2026-09-20。
ユーザー指示の水・高山・隙間の修正と、軽量化最適化指示書 R1 の優先項目を反映した。

## 地形と戦闘

- 水色の地形は河川。`Resources/Terrain/WaterBlock.prefab` と専用マテリアルを追加し、河川の生成に使用する。水上への移動・配置、途中に水を挟む移動、斜めの角抜けを拒否する。
- `Resources/Terrain/HighMountainBlock.prefab` と専用マテリアルを追加し、高さ3の高山へ使用する。山は移動・視界・近接・直線射撃を遮断する。
- ユーザー回答に従い、弓兵 Archer・投石 Bomber・迫撃砲 Mortar の遠距離（2マス以上）の放物線攻撃だけ山越し可能。Crossbow・Magicsniper は直射扱い。通常の射程・目標の視認条件は引き続き適用する。
- 実戦の攻撃候補・ダメージ判定・攻撃施設・強敵の攻撃に地形判定を適用。AI先読みは観測済みの山・水だけを取り込み、同じ遮断規則を使用する。
- 地面の下は基礎までブロックを積み、霧の下段も基礎まで延ばして、下から見える隙間を塞ぐ。

## 軽量化・保守性

- 霧を16×16セルのチャンクメッシュに変更。未探索・探索済み・現在視界の論理状態を維持し、変更のあったチャンクだけメッシュを再構築する。
- Minimaxの移動候補は兵種別の相対座標をキャッシュ。全マップ走査を廃止した。
- 敵ターン全体の思考予算を `AICommander.TurnThinkingBudgetMs` に統一（初期値3000ms）。師団提案・実行にも予算を適用。重要局面に深い探索を絞り、設定深度と完了深度を別表示する。反復が完了しなかったスコアを採用せず、1段も完了しなければ先読み補正を加えない。
- 独立勢力を含む戦闘対象を `CombatRegistry` に登録し、活動・非活動・復元時のライフサイクルを統一。
- 近傍の味方・敵を空間インデックスで検索。味方密度・ヒーラー・最寄り味方・反撃予測を盤面更新の世代ごとにキャッシュ。更新時に失効する。
- 近傍列挙を割り当てのない構造体へ変更。探索候補は深さ別バッファ、貪欲探索は専用バッファを再利用。保持するキラームーブは値をコピーし、バッファ再利用で壊れないようにした。
- 先読みの視界用HashSet、評価用ユニットリスト、固定候補配列を再利用。既存の盤面プール、Alpha-Beta、TT、Zobrist、候補数制限は継続使用。
- AI詳細ログはEditor/Development限定。ログ用StringBuilder等の前処理も条件付きコンパイルにした。警告・エラーは残す。
- `TagManager.asset` にあったUnityパーサーエラーの原因となる空レイヤーの記法を修正。レイヤー番号・名称は維持。

## 旧セーブ

従来は河川上へ配置できたため、復元したユニットが水・山にいる場合は空いている最寄りの陸地へ移す。水上の既存クリスタル・建物は足元を陸地として維持し、その例外セルをセーブへ記録する。建物を後で撤去しても再ロードで突然水に戻らない。元の保存スロットは検証に使用していない。

## 検証結果

Unity Editorの隔離コピーで、コア54項目・シーン43項目・地形／最適化37項目、計134項目が成功。通常のWindows x64ビルドは成功し、BuildReportはエラー0・警告0。生成済みAssembly-CSharp.dllのILを検査し、DevelopmentLog.Logへの呼び出しが0件だった。

元プロジェクトのUnityでも新規ゲームの起動と高山プレハブの生成を画面で確認した。キー入力による全操作や、全ランダムシードでの地形バランスまでは網羅していない。

| 霧の計測 | 35×35 | 40×40 |
|---|---:|---:|
| 旧方式の描画オブジェクト数 | 7,350 | 9,600 |
| 新方式の描画オブジェクト数 | 54 | 54 |
| 旧方式の生成時間 | 39.667ms | 54.448ms |
| 新方式の生成＋初期メッシュ構築 | 19.546ms | 20.899ms |
| 旧方式の対象ネイティブメモリ | 12.26MB | 15.69MB |
| 新方式の対象オブジェクト＋メッシュ | 8.44MB | 10.97MB |
| 状態不変100回更新 | 4.176ms | 5.492ms |
| 同更新のGC.Alloc | 0回 / 0B | 0回 / 0B |

旧方式は元の霧プレハブをセルごとに生成した比較用実装。メモリはProfiler.GetRuntimeMemorySizeLongによる対象オブジェクト・コンポーネント・新規メッシュの集計で、共有マテリアルやアプリ全体のメモリを含まない。Editor/batchmode/nographicsの単発比較であり、GPU時間・FPSや実機全体の改善率を示すものではない。

脅威度100で視界内に敵がいる戦闘テストでは、全体思考3032.732ms（予算3000ms）。設定深度20に対して完了深度4。Editor詳細ログ込みのGC.Allocは170,428回・6,334,200B。割り当てはまだ残るが、視界推定の毎候補HashSet生成等を除去した。予算は同期処理の区切りで判定するため数十ms程度の超過は起こり得る。

初期検証で利用したGC.GetAllocatedBytesForCurrentThreadは、このUnity環境で割り当てを検出できず不採用とした。上記の割り当て値は、既知のbyte配列確保を検出できることを先に検証したUnity ProfilerRecorderのGC.Allocから得た。
[ProfilerRecorderの公式仕様](https://docs.unity3d.com/ScriptReference/Unity.Profiling.ProfilerRecorderOptions.CollectOnlyOnCurrentThread.html)を参照。

## 再検証

`Tests~/README.md` に隔離コピーでの手順を記載。結果の抜粋は `Tests~/OptimizationValidationResults.txt`。
検証用ビルドはカタログ等のテストデータを含む隔離コピーで作成したもので、配布用ビルドではない。

地形のメッシュ統合、マーカー・エフェクト・頭上UIの追加削減は指示書上の検討候補として残る。今回の大きな対象は霧とAI探索であり、長時間プレイや多数ユニット時の継続プロファイルは別途必要。
