# AI自動操作で勝利しても脅威度が上がらない問題

2026-10-19

## 原因

`DeveloperPlayerAIWasUsed` はF8の自動操作を一度でも利用すると、その試合中は解除後も保持され、セーブにも引き継がれる。従来の `TryRecordMatchResult` はこのフラグがあると正常終了を返しながら結果保存を省略していた。そのため正式に勝利しても脅威度・戦績が更新されず、結果画面に「進行記録なし」と出ていた。

## 修正

- 手動操作・AI自動操作とも、正式な勝利または時間切れ勝利で保存済み脅威度を1上げる。
- 敗北と引き分けでは上げず、最大100を守る。
- 同じMatchIdの再通知、ロードし直した同じクリア済み試合、AIのON/OFF切替では二重加算しない。
- 試合完了ID・戦績・脅威度を従来と同じ原子的保存でまとめて更新する。既存save/profile形式は変更しない。
- 自動操作の由来フラグは互換性のため保持するが、進行の失格条件にはしない。対人傾向の学習抑止条件は変更しない。
- 結果UIは実際の保存結果に従い「次の脅威度: 20 → 21（+1）」などを表示する。

次の新規ゲームは従来どおり保存プロファイルから難度を読み込む。途中セーブの再開はその試合が始まった難度を維持する。

## 回帰検証

`Tests~/ThreatClearProgressionTests.cs` の `Run()` はOS一時フォルダだけで、通常/AI勝利、時間切れ勝利、重複、AI利用履歴を含むsave、旧save移行、上限、未来形式の保護、保存失敗表示を検証する。

`PlayMode(GameSystems, TurnGenerator)` は隔離されたUnityValidationの実Play Modeから、結果保存・結果UI・タイトルUI・次ゲームAI初期化の経路を確認する。元の試合状態を終わらせず、一時UI・自動操作フラグ・乱数・AIモード・保存先を復元する。

自動対戦の検証ランナーは専用company/productまたは一時保存scopeを使用すること。開発AIの利用だけでは勝敗進行を抑止しない。

RootがUnityの実Play Modeで保存40項目・結果UI/タイトル/次試合10項目の成功を確認。アサシン変更を含む最終Unity Test Frameworkは10/10、Windows64非開発ビルドもエラー0・警告0で成功。実行ログは `PerformanceData/board-feedback-ai-20261019/` を参照。
