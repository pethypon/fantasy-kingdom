# 複数ターン作戦・作戦学習の実装報告

日付：2026-10-10。対象：添付された「AI複数ターン作戦・作戦学習システム Codex実装仕様書」。

Strategy → Operation → Step → Actionの階層を追加した。既存のAIPlan、Governor、探索R2、Minimax、行動学習を利用し、主目標の達成を作戦の採点基準にする。作戦の0～100点を行動の点数へ直接足す処理はない。

設定はUnityの **Fantasy Kingdom → AI → 複数ターン作戦の設定**。`Assets/Resources/AI/OperationConfig.asset` を日本語Inspectorで編集する。標準では脅威度10以降で有効。同時作戦は最大3、主作戦は1つ。目的ごとの配点合計は100点で、異常な合計はInspectorに警告を出す。

## 実装した10段階

| 段階 | 内容 |
|---|---|
| 1：作戦モデル | OperationId、主目標、元の目標、開始状況、手順、期限、割当役割/駒、行動記録、変更履歴を値データで保持。全軍を1つの作戦へ割り当てず、王は通常の作戦割当から除外する。 |
| 2：目的別の採点 | 目的達成を標準40点とし、軍事成果・生存・効率・位置・領土・経済・情報・防衛・時間・軍活用・準備・成功後の活用・危険管理を正規化して目的別配点へ適用。主目標未達成は最大69点。自軍クリスタル破壊、壊滅、経済Collapseなどは100点の対象外。 |
| 3：作戦の終了と変更 | 自軍ターンごと、および観測が更新された時に継続/再計画/中断/終了を評価。停滞時は手順を再計画し、最大期間を超えれば評価して中止する。緊急防衛・経済危機での合理的撤収を通常の大失敗と区別。中断期間は期限から除外する。 |
| 4：行動との接続 | 実行前にAIActionRecordへOperationId/StepIdを付け、実行後の結果を作戦へ送る。撃破LifeIdとArtifact獲得EventIdを正式イベントから受け取り、敵が見えなくなったことや表示上のHPだけで破壊成功としない。 |
| 5：作戦経験 | 一般化した状況・目的・手順で経験を保存。1件では候補選択へ使わず、標準2件から使用、10件で最大信頼度。通常の行動学習と別のProfileへ記録。暫定評価と重複した終了事件は学習しない。 |
| 6：作戦選択 | 上位Strategyと実際に取得できる情報から候補を生成。戦略優先度の比較を先に行い、その内部で経験・性格・プレイヤー傾向・危険を反映。行動への補正は標準最大3の小さな値で、合法候補や緊急防衛を取り消さない。 |
| 7：関連行動への還元 | 主目標が成功した時だけ、直接の達成・因果のある偵察/支援/接近へ小さな追加評価を返す。1行動あたり標準最大1、既存の行動合計上限と後続報酬上限も守る。無関係・失敗・負評価の行動は対象外。作戦失敗でも良い行動の評価を下げない。 |
| 8：作戦日記 | 現在の日記にGoal、Plan、Expected、Actual、Score、成功/失敗理由、Lessonを追加。進行中は暫定表示で100点にせず、学習しない。目標変更前後・実際の評価変化を表示し、架空の内心を生成しない。 |
| 9：保存・復元 | ゲームセーブをv6へ更新。v5以前の探索・行動学習を保持し、作戦履歴がない場合は空の状態から開始。進行中の目標・手順・割当・変更履歴・観測/撃破/獲得の重複防止を復元。作戦経験は独立v1 JSON、temp/backupと不正entryの救出に対応。 |
| 10：検証 | 必須T01～T20を含む作戦Core39件と実盤面/Commander/保存/故障時復帰21件、既存の回帰テストを実行。長時間対戦・通常Windowsビルドの最終結果を下記に記録する。 |

ゲームから実際の根拠を取得できる偵察・経済回復・クリスタル防衛・観測済み目標への攻撃・陽動/迂回/包囲・Artifact取得を候補化する。Goal enumや評価器の拡張用定義を理由に、新しいゲームルールを作る処理はない。作戦A→作戦Bの連鎖学習は仕様書の初期実装範囲から除外した。

## 安全性と軽量化

- 作戦の実行位置・LifeId・HPなどは戦闘中のデータに限る。試合間の作戦Profileには座標、GameObject、Transform、現在HP、駒の識別情報を保存しない。
- 観測していない敵の参照が候補に残っていても、現在位置・HPを使って作戦評価を変えない。敵側と開発用プレイヤー側の両方で実盤面テストを実施した。
- 陽動は実際に確認した守備兵の移動で判定する。新しい援軍が到着した場合は開放された経路として数えず、敵が視界から消えただけでも成功としない。
- 未確認の敵戦力と観測済み戦力比から予想危険を保持し、実損失と比較する。予想危険を常に0として扱わない。これらの値も設定から調整できる。
- 特徴量は盤面generationで再利用。作戦の同時数、経験、行動記録、割当、変更履歴、事件履歴を制限する。作戦経験の検索はDictionaryで、陽動の守備兵比較も索引を使う。
- 操作や選択のたびにJSON保存しない。保存は既存の日記/戦闘終了境界とゲームセーブの時。開発用プレイヤーAIと開発用試合の経験はメモリ内に隔離する。
- 作戦処理の例外はその機能内で隔離し、通常AI・行動学習・ターン終了を継続する。行動学習が無効の場合も作戦用の観測経路を用意した。
- ターン終了時の盤面再計算を行動学習と共有し、二重の再計算を避ける。旧AIPlanの別目標への迂回地点を新作戦へ混ぜない。

## 主なファイル

- `Assets/Script/Gamesystem/TurnSystem/Enemy/Operation/`：作戦モデル、Manager、FeatureExtractor、Scorer、理由分析、Config、LearningProfile、Persistence、Diary。
- `AICommander.Operations.cs`：既存Commanderとの接続、例外隔離、正式イベント、保存/日記境界。
- `Reflection/AIActionReflectionSystem.Operations.cs`：関連行動への限定した還元。
- `Assets/Editor/AIOperationConfigEditor.cs`：日本語Inspectorと配点警告。
- `Assets/Script/Tests/AIOperationCoreTests.cs`、`Tests~/AIOperationIntegrationTests.cs`：作戦検証。
- 既存のReflection、選択、日記、SaveSystemの収集/復元/移行に必要な接続を追加した。既存機能とユーザーの編集は保持。

報告いただいた `AIOperationConfig.Active`、`AIOperationManager.Refresh` の不足は実装済み。Unityのコンパイルで解消を確認した。
