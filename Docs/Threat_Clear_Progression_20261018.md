# クリア後の脅威度進行

2026年10月18日。ユーザー指定「ゲームをクリアしたら脅威度を+1」を通常の勝敗処理へ統合。

## 動作

- 通常勝利・時間切れ勝利のどちらも、次の新規ゲームの脅威度を **1だけ**上げる。上限100。
- 敗北・時間切れ敗北・引き分け・途中終了では上げない。
- 開発者用プレイヤーAIを一度でも使用した試合は従来どおり進行記録から除外する。保存・再開でもこの印を保持する。
- クリア画面に「次の脅威度: 15 → 16（+1）」を表示。100では「上限」と表示する。
- AI内部に残っていた「短期決着で+2/+3、経済崩壊でさらに+1」の処理も+1へ統一する。学習の失敗原因分類は残す。

## 重複と保存失敗への対応

新規試合には専用の識別子を1つ発行する。チェックポイント・複数スロットへの保存・再ロードで同じ識別子を維持する。終了時は識別子・勝敗通算値・脅威度を同じプロファイルへ原子的に保存する。完了済みの試合は別の終了結果になっても再加算しない。リトライして新しく始めた試合は新しい識別子となる。

`GameEndState.Entry()` 自体も一度だけ実行する。保存できなければ結果画面に保存失敗を表示し、成功したような+1表示や勝利実績の二重加算を行わない。既存の復旧用世代保存・未来スキーマ保護を利用する。

完了識別子は100,000試合を上限として保持する。古い識別子を自動削除して古いクリアの再加算を許すことはしない。上限では明示的に保存失敗とし、現在のプロファイルを保護する。通常ターン中の処理・探索候補生成にはこの履歴を参照しない。

## 互換性

- ゲームセーブはv9、プロファイルはv2。既存の移行段階を維持し、v8→v9を追加。
- v0〜v8は、元から保存されている地形生成・クリスタル・AI乱数/学習試合識別情報から安定した識別子を生成する。同じ旧ファイルを再ロードするたびに新しい試合扱いにはしない。ターン・保存日を識別子に使用しない。
- 元の旧ファイルは読み込みだけでは書き換えない。次回保存で現行形式になる。
- 識別情報を持っていなかった旧版で、生成条件もAI識別情報も完全に同一だった別試合を後から厳密に区別することはできない。新規試合には個別の識別子があるため、この制約はない。
- v1以前のプロファイルに完了記録を遡って捏造せず、既存脅威度・勝敗通算値を保全して新しい記録を始める。
