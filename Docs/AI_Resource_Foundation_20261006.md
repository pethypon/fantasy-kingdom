# 資源基盤AI：R2経済管理＋資源優先仕様 R1

2026-10-06。対象は敵AIと開発用プレイヤーAI。追加指示に合わせて、木材・石材・鉄・魔石・小麦・パン・水・市民の8資源を評価する。

## Unityで調整する場所

`Fantasy Kingdom → 開発スタジオ（日本語） → 陣営・ゲームルール → AIの経済・生産判断（R2） → 資源基盤を整える経済AI（全資源）`

各資源の最低備蓄、計画費用の見込み、不足・回復・余剰の充足率、回復計画を維持する期間、建築の費用回収期間、評価係数を変更できる。ゲームルールの適用を有効にして保存する。生産量・建築費・強化費・駒の費用は既存の建物／駒データを使用する。旧 `plannedBuildCost` は保存互換のため残すが、現在の計画費用は実データから取得する。

## 判断の流れ

1. `StrategicEconomyForecast` が自陣営の在庫・実際のレベル別レシピ・維持費・市民消費を予測する。クリスタルの減衰する一時収入は恒常生産と分ける。
2. `StrategicProductionDemand` が資源ごとの不足供給、安全在庫、上流の生産停止を診断する。
3. `AIBasicResourceEconomy` が近い将来の実費、停止する計画、供給源、資源の必要度を評価する。各資源への効果を合算し、単一資源だけを追い続けない。
4. `AIStrategicGovernor` が優先順位、予備資源、予測上の新たな支払い失敗を判定する。候補選定と実行前の両方で確認する。
5. 建築・強化・召喚が成功したら盤面と経済診断を更新する。APは現在実行可能な供給改善のために予約する。

開幕の追加加点は木材・石材・水に残す。他の資源も実需要・備蓄・停止計画によって優先される。回復開始と解除の条件を分け、同一ターンの再診断では継続ターン数を増やさない。資源を消費する緊急防衛は、視認した敗北条件への重大な脅威に限定する。

確率生産は供給経路の期待値として扱う。維持費を必ず払えるという確約には使わない。市民は食料、人口上限、計画支出後の再成長、住宅による容量改善を評価する。

## 実行経路と負荷

取得手段は既存の建築と施設強化を使用する。資源の付与や新しい採取ルールは追加しない。建築不能時も、実行可能な強化や安価な自作施設を検討する。実行可能な供給経路がなければ、架空の費用のためにAPを保持し続けない。

通常候補、先行建築、直接建築、最終フォールバックは同じGovernorを通す。施設強化は末尾に追加した `AIActionType.Upgrade` を使い、既存の保存値は保持する。`BuildSystem.TryUpgrade` の実際の費用・AP・所有陣営で再検証する。施設レベルを持たない戦術Minimaxは強化の仮想効果を捏造せず、実経済の評価を保持する。

診断、施設評価、所有施設一覧、AP予約を盤面の世代ごとに再利用する。自作施設の候補は実需要で上位16定義、最大32配置に制限し、一覧末尾の必要施設も選考する。判断ログは既定で無効。

## 検証結果

Unity 6000.3.8f1 の隔離プロジェクトで実施。

- `SceneSmoke` 全統合テスト成功。R2の検証74項目、資源基盤の検証113項目を含む。
- 両陣営で実建築・強化・予備資源・AP支払いを確認。序盤16ターンの実経済、人口と食料、確率生産、多数の自作施設、判断の継続と切り替えを検証。
- 3条件で、それぞれ50ラウンドの実AI対戦と別の60ターン経済耐久テスト成功。対戦と耐久のターン数は別集計。
- 通常Windows x64ビルド成功：エラー0、警告0。
- コード差分の `git diff --check` 成功。

耐久テストは軍の維持費を20・40ターン目に増やし、従来の棟数制限を越える増設と支払い継続を確認した。テストは一時データを使用し、ゲームの資源・駒・ルール資産へ保存しない。

隔離実行でUnity Editor検索インデックスの既知の起動時例外が各条件1回発生した。ハーネスは該当するEditorスタックだけを明示して別集計する。ゲーム由来の例外と他のエラーは引き続き検証失敗とする。

この検証は全ての対戦・自作データでの経済最適性を保証するものではない。将来のルールや生産レシピ変更時は `BasicResourceEconomyTests` と `EconomyR2LongRun` を再実行する。
