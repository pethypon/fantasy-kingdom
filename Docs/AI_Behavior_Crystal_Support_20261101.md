# AI行動・クリスタルHP・部隊支援の調査と修正（2026-11-01）

クリスタルに通常兵の自然回復が適用される不具合を実行環境で再現し、修正した。ダンジョン報酬による最大HP増加も通常対戦で確認したが、これは既存仕様なので維持した。AIは４体部隊を自発的に編成して正式な移動命令を実行し、聖騎士も生産した。ただし、通常対戦での回復スキル使用と勝利までの進軍は確認できていない。部隊連携全体の完成とは評価しない。

証拠は [Validation/AI_Behavior_20261101](Validation/AI_Behavior_20261101/README.md)。以下は実行結果と推定を分けて記す。

## 実行範囲

- Unity 6000.3.8f1、元プロジェクトから作成した分離検証プロジェクト。既存SampleSceneのNew Gameと本番データを使用。
- 通常自動対戦９試行、３マップシード、Enemy脅威度15/35、Player開発AI15。合計1280ラウンド／2560所有者ターン。全試行で実際にフレーム・戦闘・経済・ターンが進行。
- 資源、軍、AP、HP、敵情報、思考予算、timeScaleを試験から補正していない。既存開発AIモードではゲーム時間制限が無効。制限時間つき手動プレイは未検証。
- 修正前２試行、攻撃優先度のみ変更２試行、部隊・経済・回復除外を含む版３試行、同じゲーム挙動で回復診断を補完した最終版２試行。
- 別途、実Play Modeの制御試験とネイティブEditorのコア試験を実行。制御試験の配置・負傷・作戦は手動準備であり、自然なAI判断の証拠にはしない。
- 既存の作戦・部隊機能は動作。R4高次自律プランナーは既定の無効／shadow状態であり、R4の複数段階計画が有効になった結果ではない。

## 1. クリスタルHP増加の原因

### A. 不具合：通常兵向け自然回復

本番のメインクリスタルは古いデータ上 `Type.Unit`。従来の `NaturalRecoverySystem` は型だけで判定し、５無傷ターン後の10%自然回復を適用していた。

再現手順：New Gameで実在するメインクリスタルを500負傷させ、所有者ターン終了処理を７回通す。両陣営で4500から5000へ回復し、最大HPは5000のまま。制御試験２／２対象で再現した。

変更：`Kind.Crystal` と `Kind.SubCrystal` を自然回復の対象から明示的に除外。現行のターン終了経路と旧互換経路で同じ判定を使う。修正後２／２で4500を維持し、通常兵の自然回復は引き続き動作した。

副作用：クリスタルを放置して回復させる挙動はなくなる。報酬、明示的な回復、獲得済み最大HPは変更しない。

証拠：[修正前](Validation/AI_Behavior_20261101/crystal-before.txt)、[最終制御試験](Validation/AI_Behavior_20261101/formal-playmode-final.txt)。

### B. 仕様：ダンジョンのCrystalShard報酬

最終の通常対戦（シード141421、脅威度35）では、Enemyの最大HPがラウンド11に6000、61に7000、71に8000になった。各回で実回復1000と `DungeonSystem.BuffCrystal → GrantArtifact → ProcessTurn` を記録した。３回とも報酬による増加で、自然回復でもロードの反復加算でもなかった。

既存ルールは報酬時に最大HP＋1000と1000回復。ダンジョンの周期報酬が再発生すれば追加獲得できる。同一ラウンド、相手側処理、報酬以外の処理で重複付与しないことも制御試験で確認した。この報酬量・周期・上限は変更していない。

証拠：[実呼出しを含むHP記録](Validation/AI_Behavior_20261101/behavior-release-growth/01-141421/crystal-hp.csv)。`UniqueRewardSystem` にも作者設定による別のHP加算経路があるが、今回の３回の原因ではない。全セーブ条件での増加原因を網羅したとは言わない。

## 2. 補充を止める攻撃優先度

修正前シード271828のEnemyは、資源・維持費・APの審査を通過したDragonKnight召喚候補がP3なのに対し、サブクリスタルへの非撃破攻撃がP2となり、APを使い切る例があった。記録範囲で29ラウンド・189候補サンプル。候補サンプルは独立した機会数ではない。

変更：視認済み・非武装の施設／サブクリスタルへの通常攻撃で、その一撃では撃破できないものを通常の補充・展開と同じP3へ。緊急防衛、武装施設、勝利対象、撃破可能な攻撃、複数駒の連携撃破の優先度は維持する。隠れた敵を追加参照しない。

注意：修正前のサブクリスタル攻撃373回は合計5000HPを削っていた。ダメージ０の無意味な反復ではなく、本番HP5000の長期攻城でもあった。「全て無駄な攻撃」とは評価しない。

最終Combat試行ではP3の増兵候補がP2攻撃に負けた該当サンプルは０。ただし別シードでは通常戦闘などによる優先負けが残る。純粋な補充数や勝率が常に増える変更ではない。

副作用：施設の撃破が後回しになる場合がある。狙いは資源・維持費を満たす補充や偵察にもAPを回すこと。実戦結果を見ずに攻撃全体を弱める変更はしていない。

## 3. ４体部隊と回復職

変更前は既定の編成サイズと回復役を必要とする人数が噛み合わず、３～４体の戦闘部隊に回復役の需要が出にくかった。標準サイズを４体へ揃え、戦闘部隊３体以上から回復役を１枠含める。偵察部隊の構成は維持。実際の編成と不足役の補充需要が同じ計算を使う。

また、予定兵の継続維持費を35%等の重みつき値でしか見ないと、必要な生産施設を準備できず購入を待ち続ける。次の具体的な補充兵１体については、実際の維持費を満たす生産需要を計上する。これは将来の生産目標であり、現在の維持費に架空の兵を加えたり、資源・市民・AP・予備費の審査を免除したりしない。

### 回復の確認と限界

制御Play Modeでは両軍とも４体の同一作戦に白魔導士を含め、AI生成候補から正規スキルを実行し、実AP支払いと仲間のHP増加を確認。その後４体全員が正規の移動命令を実行した。

通常対戦では聖騎士は生産したが、回復スキルの実行は確認できなかった。最終Combat試行にはHolyKnightSanctuaryの生成候補91サンプル／17所有者ターンがあり、AP不足ではない。選択時の最高評価も負で、周囲の味方がほぼ無傷、負傷者が範囲２の外という例を確認した。回復役の位置と負傷者の接近、回復のために一時集合する判断が次の改善対象。移動・攻撃不可かつ被ダメージ２倍になる聖騎士を、使った実績だけのために強制発動させない。

回復診断自体にも欠落があり、従来の `RecordHeal` はHPを回復しても `HpChangeCommitted` を通知していなかった。Editor／Development Build限定で実回復を通知するよう補完。最終２試行でユニット回復を計75件記録したが、全て通常の自然回復であり、回復職の成功件数として数えない。旧診断の空ファイルを「回復０」の証拠にも使わない。

## 4. 残る問題と改善方法

1. **決着への圧力不足（高）**：全試行が80/160ラウンド上限で未決着、勝利対象への攻撃０。敵国への移動や経済施設への攻撃はあるが、勝利対象の発見・接近・包囲へ接続できているとは言えない。低ダメージの長期施設攻撃と、本隊の目標切替・経路・AP配分を分けて追う必要がある。未視認クリスタル位置の取得による解決は不可。副作用として、単に攻勢評価を上げると司令官の無謀な前進を再発させ得る。
2. **回復の集合判断（高）**：前述の２試行とも回復スキル使用０。回復役が患者へ近寄るだけでなく、負傷者も同じ支援位置へ向かう協調が必要。到達可能な安全位置、実スキル範囲、APを共有条件にし、攻城中・退却中の中断復帰を試験する。過剰な集合は前線停止や範囲攻撃への弱さを生む。
3. **初期軍の未払い（高）**：全９試行で敵側６ラウンド分の未払いを観測。修正した将来兵の生産需要だけでは初期軍の経済問題は解消していない。初期生産の立ち上げと固定維持費５倍の影響を別試験で比較する。資源無料化や維持費の無断変更はしていない。
4. **スパイクと長時間負荷（中～高）**：最終Combatはp95約16.4ms、最大約510ms、約181→234MiB。最終growthはp95約6.3ms、最大約650ms、約181→232MiB。バッチEditorと診断を含む値。数時間のリーク、製品ビルド性能、終了時のUnityネイティブメモリ表示の原因は未検証であり、解消済みとはしない。
5. **少数の実行拒否（中）**：最終CombatでPlayer２／Enemy１のFailedActions。致命的例外やターン停止はなかったが、候補作成と実行直前の状態変化の詳細は継続確認が必要。
