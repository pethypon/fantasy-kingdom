# Unity・パッケージ・保存形式の更新検証

更新日: 2026-10-11。

## 更新前

- 製品、ソースCommitと差分、.meta、manifest、packages-lock、ProjectVersion、ビルド情報、テストログを保管する。
- 対戦セーブ、プロフィール、AI学習データをコピーする。利用者の保存先をテストで上書きしない。
- 隔離コピーで現在のSceneSmoke.RunとReleaseValidation.Runを通し、比較対象を記録する。
- 変更するUnity／パッケージ／保存Schemaを一つずつ明確にする。

## 更新中

- 公開した固定キー、数値enum、コンテンツID、Prefab／ScriptのGUID、Resources読込名を維持する。
- SerializeField名の変更には旧アセットのロード確認と必要なFormerlySerializedAsを含める。
- Schemaを増やす場合は一段ずつのMigration、旧fixture、最新round-trip、未来Schema拒否、破損回復を検証する。
- 乱数列やAI採点の変更は意図と再現性への影響を記録する。表示・カメラでゲーム用乱数を消費しない。
- 第三者アセットの元フォルダとライセンス文書を保持する。

## 更新後

| 検証 | 確認事項 |
| --- | --- |
| 旧セーブ | 全VersionのMigration、個体・定義IDの復元 |
| 保存障害 | 中断、壊れたJSON、バックアップ回復、未来Schema保護 |
| 登録 | 空・重複ID、消えたPrefab、スキル・遭遇の参照切れ |
| ルール | ダメージ、時間切れ、AP、移動、経済、勝敗、ターン順 |
| AI | 観測制約、探索、経済、作戦、学習、乱数と行動の再現 |
| 操作 | 敵ターン中の確認、選択、HP、霧、メニュー、日記、カメラ |
| 長時間 | 500 own turns、後半CPU、フレームGC、メモリ、保持件数 |
| 製品版 | 開発用テスト／fixtureを含まない通常Windowsビルド |
| ビルド情報 | 製品内とsidecarの一致、生成アセットの後片付け |

500ターンfixtureは固定ワークロードです。すべての戦況やOSの性能を代表しません。CPU・GC・メモリ比較にはEditorのProfiler記録やテスト自体の割当も条件として記録します。

保存の読込保護はマップ各辺256マスまでです。旧MapCreateのCustom Inspectorはこれ以上の値も指定できたため、256を超える既存保存を更新前に調べてください。大きい保存を小さく切り詰めてロードせず、原本を保持したまま対応する版と読込上限を別途検証します。通常の制作スタジオの設定範囲は16～80マスです。

失敗はコピーで直し、元の制作環境と保存データを保持します。新版で再保存したデータを旧版へ戻せると想定せず、更新前の原本を使います。更新ごとの検証が長期互換性を維持する条件です。
