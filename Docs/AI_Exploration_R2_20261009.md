# AI索敵・探索ループ防止 R2

対象仕様：`Fantasy_Kingdom_AI索敵・探索ループ防止_R2_Codex仕様書.docx`。2026-10-09。

## 実装した動作

- Scoutごとに探索地域と目標を保持する。最近見た場所を次の探索目標として繰り返し選ぶことを抑える。
- 既知と未知の境界を地域にまとめ、未探索量・情報の古さ・危険・移動距離・訪問・他Scoutの担当を評価する。遠方の候補を距離だけで除外しない。
- 視認と実訪問を別々に記録する。初期値は直近5ターンの情報を低評価、30ターン以上古い重要情報は再確認の候補とする。
- 自軍ターンごとの固定長履歴から往復・小範囲の周回を検知する。新規視界も目標への前進もない状態が3ターン続いたら再計画する。失敗した地域は一定期間避ける。
- 複数Scoutを別の地域へ割り当てる。Kingを探索担当にしない。緊急防衛では目標を中断し、解除後に再開する。
- 既知の地形と観測済みの危険から、計算量に上限のある迂回経路を求める。経路を証明できない場合は未到達と断定せず、近距離の移動評価へ戻る。
- 開発用プレイヤーAIにも、その陣営自身の視界・記憶で同じ処理を適用する。

未知の敵・施設・地形を直接読む処理を探索計画へ追加していない。建築、召喚、戦闘、王の生存と緊急防衛の既存ルール・優先順位は維持する。

## 保守性と計算量

`Assets/Script/Gamesystem/TurnSystem/Enemy/Exploration/`へ、値モデル・計画・盤面変換・保存復元・履歴・経路・診断を分けた。戦闘の候補生成と探索計画を同じ巨大クラスへまとめていない。

| 処理 | 標準の上限・再利用 |
|---|---|
| 地域の大きさ | 16×16マス |
| 比較する地域候補 | Scoutごとに64地域まで |
| 地域更新 | 視界・既知地形の変化時と4ターン間隔 |
| 位置履歴 | 8自軍ターン、同ターンの移動は最後の位置へ更新 |
| 既知の経路探索 | 2048位置、保持経路4096位置まで |
| 経路の再利用 | 最大64駒分、標準8ターン。成功と未証明の結果を再利用 |
| 移動候補の経路評価 | 既存経路への参照・接続を利用。候補ごとにA*を実行しない |
| 診断記録 | メモリ256件。JSONLは標準OFF、32件まとめ書き、標準4MiBで交代 |
| 通常AIの合法移動候補 | 全マップの走査をやめ、駒の実際の移動マスクの周辺だけを調べる |

経路残量は移動距離と危険の戦略的な目安であり、実際のAP消費量ではない。移動の実行とAPは既存の共通ルールを使用する。

距離の基準が変わっただけでは進捗を付与しない。経路の再計算・危険情報の更新・旧保存形式の補正があっても、停滞時計を延長せず、履歴の位置と新規視界を残す。

## Unityで設定・確認する場所

1. **Fantasy Kingdom → AI → 探索・ループ防止の設定**。日本語Inspectorから時間、評価の重み、安全性、計算量、ログを調整する。設定はゲーム開始前に変更する。
2. **Fantasy Kingdom → AI → 探索判断の確認（日本語）**。再生中に「最新の判断を取得」で駒ごとの目標・経過ターン・残り目安・新規視界・再計画の理由・候補評価を確認する。
3. 開発スタジオ上部の「AI探索の設定」からも設定へ移動できる。

設定アセット：`Assets/Resources/AI/ExplorationSettings.asset`。

判断画面は手動更新。表示のたびにマップ全体やログファイルを走査しない。常設のゲームHUDは増やしていない。

任意のJSONL保存先：`Application.persistentDataPath/FantasyKingdom/AI/Exploration/exploration-Enemy.jsonl`。開発用プレイヤーAIは別ファイル。

## 保存互換性

ゲームセーブはv5。旧v4からの移行で既存の資源・生産位相・自己評価記録を保持する。探索記憶、駒ごとの目標、訪問と履歴、地域の担当時刻・ループ回避期間を保存する。読み込み後は駒の生存IDで新しいRuntime IDへ接続する。

探索DTOはv3で、開発途中のv2も読み込み可能。未知の形式、範囲外の座標、無効な数値・ID、過大な件数を検査する。非表示地域を読み込み時の盤面走査で再取得しない。

以前報告された`GameEndState.cs`のCS1061も修正済み。結果画面は`TimerSystem.LastTimeUpResult`と`TimeUpReasonText`へ依存せず、共通の結果理由処理を呼ぶ。

## 検証

Unity 6000.3.8f1の隔離したUnityValidationで検証する。編集用プロジェクトは停止せず、実プレイ・通常Windowsビルドを分けて確認する。

最終結果は検証完了後に追記する。

## 運用上の調整点

停滞3ターンや危険評価は初期値で、マップの規模と駒の自作移動マスクに応じて調整できる。未知の地形を使わないため、すべての目標へ必ず到達できるとは仮定しない。探索中に得た情報と実際の移動失敗から再計画する。

前の自己評価・AP・維持費・生産調整の内容と検証記録は`Docs/AI_Reflection_Balance_20261008.md`にまとめている。
