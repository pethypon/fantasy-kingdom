# AI進化仕様 v1 対応（2026-10-02）

## 今回の実装

- `AIThreatLevel.MinLevel` を30から1へ修正。既存セーブの30以上を強制的に下げない。
- レベル1から攻撃を加点。レベル2で撃破、3で孤立した敵・安全な成長、4で短期記憶、5で連携、6で先読み、7で偵察の分担、8で施設・SubCrystal攻撃を強化する。
- 接敵していても経済完成まで攻めない判定順を変更。最低限の生産と戦闘を同じ候補集合で比較する。
- 固定の建築→偵察→拠点→召喚→師団行動フェーズを通常実行経路から外し、一行動ごとに盤面・方針・ロールを再評価する。旧HierarchicalModeプロパティは互換用で、有効化されない。
- `AIEvolutionPolicy` が観測済みの攻撃目標を3ターン、レベル10以降は5ターン保持する。危機、部隊の大幅な損失、目標地点が再視認され空だった場合、期限切れで解除する。未視認の実Transformは追跡しない。
- 建築の支出目安は初期APの15%／25%／30%。超過時は減点するソフト予算で、厳密な支出上限ではない。既存の合法性・資源・AP判定は引き続き実行直前に適用する。
- 安全に次レベルへ到達する攻撃に小さな加点を与える。撃破加点を大きくし、盾で無効になる攻撃には撃破・成長の加点を付けない。XPの予測は基本ダメージ分のみで、兵舎の追加XPは保守的に未計上。
- `AIOrientation` は駒を仮に書き換えず、逆向きで可能になる攻撃・前進・探索を比較する。今の向きで攻撃可能なら、探索目的の反転は行わない。実行はプレイヤーと同じ無料AP。各駒一ターン一回まで、同じ向きは無効。実行直後に視界・盤面を更新する。
- Rotateは列挙値末尾に追加し、既存の保存値を維持。現在のMinimaxに未対応のRotateを直接渡さず、実行後の新しい向きを次の探索に反映する。

## 継続学習

`AIPlayerModel` は敵から実際に視認できたプレイヤーの構成を、敵ターン開始時に集計する。記録対象は自陣付近への侵入比率、施設比率、Scout比率、遠距離兵比率の4つ。これは観測サンプルの傾向であり、プレイヤー全軍の正確な構成ではない。

- 保存先: `Application.persistentDataPath/AIPlayerModel.v1.json`
- 保存内容: schema version、観測のあった試合数、4つの比率のみ。座標、実HP、個体参照は保存しない。
- 勝ち・負け・引き分けで保存。観測ゼロなら更新せず、同じCommanderでの重複終了通知も二重学習しない。
- 更新式: 過去×0.8＋今回×0.2。
- レベル1〜9も記録するが行動への反映なし。10で弱く反映、11〜20で過去モデルを利用、21以上では今回の観測を60%に増やす。
- 一時ファイルから置換し、バックアップを維持。サイズ、バージョン、数値範囲を検証し、破損時はバックアップ、両方破損なら初期値。保存失敗は警告にしてゲーム進行を続行。

途中セーブに今回の4比率の累計・攻勢目標は追加していない。ロード後は保存済みの対戦間モデルを読み、今回の観測と攻勢計画を再構築する。既存セーブの読み込み形式は変更していない。

## 高レベルと今後の評価範囲

既存のレベル31以上の最終視認位置・移動方向に基づく予測、偵察による射線確保を維持。51以上には安全な味方支援圏への撤退加点、71以上には主目標以外の視認済み施設へ味方と前進する加点を追加した。

これは限定した戦術評価であり、仕様書にある本格的な囮作戦・退路封鎖の長期作戦生成や、全学習指標の実装ではない。初回攻撃時刻、低HP撤退率、スキル使用傾向などは今回の永続モデルに含めていない。「レベル10で人間並み」「100で人間以上」という強さも未検証。対戦ベンチマークと実プレイでの調整が必要。

## 保守・負荷

判断ルール、向き評価、永続モデルを別クラスに分離。対戦履歴を無制限に蓄積せず4比率に集約。既存の盤面・配置候補バッファ再利用と時間分割探索を維持。新しい探索処理をバックグラウンドスレッドに移してUnityオブジェクトを読むことはしていない。

Consoleの`[AIEvolution]`に累積攻撃回数・施設攻撃回数・向き変更回数・攻勢継続状態を出力する。FPSや描画負荷の改善率は今回測定していない。
