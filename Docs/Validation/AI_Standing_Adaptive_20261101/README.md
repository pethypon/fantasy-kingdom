# 常備軍・支援編成・市民成長・自律方針の証跡

Unity 6000.3.8f1、分離したUnityValidationプロジェクトで実際にSampleSceneを起動し、タイトルの「はじめから」と開発用プレイヤーAI15を使用した。全最終試合は60ラウンド（所有者ターン120）で打切り、勝敗未決。敵はCombat、脅威度15または35。資源・初期駒・HP・AP・timeScale・思考予算の試験中の上書きはない。今回変更した本番データを通常ロードする。開発AIに既存のタイマー無効化がある。各試合は別のcompany/product領域を使い、ユーザーの学習ファイルを共有しない。R4は既定の無効/shadowのまま。

最終本番コードはe661321、入力コードSHA256はdd90e2ffe1f4e4b6034b8db7b7d853ef41ef0e953607cb871a2f248b7203badf、対象ゲームデータSHA256は1870ba8394e430163984fb7f4a5d6601a042abb401f1bd488debe082a4ce20e2。以後の差分は報告書・証跡と説明コメントのみ。実行する条件式・数値・本番データはこの検証入力と同一。manifestはAssets/Scriptと、Resources・Scenes・Prefabs・_FantasyKingdom/GameContent内の所定形式を含む。Assets/Data/Unitを含む18職種の実際の解決済みデータは各economy-definitions.json、資産個別SHAと戦闘データの不変性はunit-preservation.jsonで別途照合する。画像・モデル・フォント全バイトの保証ではない。

standing-army-finalとstanding-army-final-highが最終版。economy-balance-beforeは旧維持費設定、standing-army-releaseは常備編成のみ、standing-army-funded-coreは初期鉱山の最終調整前。名称にfinalやreleaseを含む過去試行を、最終版と混同しない。all-trial-summary.jsonは失敗した試行も含む。特にeconomy-adaptive-fundedの強い資金固定は基礎経済を止めたため不採用であり、その方式は最終ファイルから撤回した。

nation-economy.csvは自軍の各資源と軍・住宅・市民の観測。armyは王/主指揮官を除く軍。summonsは累計であり現存数ではない。市民は消費可能なストック、capacityが保有上限。住宅を建てた瞬間に市民が無料で増えるわけではない。ヒーラーは名前ではなくAIHealingCapabilityで分類する。最初のHealer召喚後に死亡した例があり、初生産時期と現在数は異なる。

records.zipは実行行動、ユニット、候補、スキル、HP変化等のCSV。各matchフォルダへ展開するとanalyze-source-runs.pyで同梱分を再集計できる。候補詳細は既存の上限で打ち切られる場合がある。実行・経済記録とは別物。観測者は報告用の全盤面情報を読めるが、AI入力へ渡さない。コードSHAとシードが同じでも実時間探索・フレーム順序のため決定論的な勝率比較ではない。

adaptiveModifierは実際に選択された行動の方針補正。最終AdaptivePolicyは7種類の平均、試行数、停滞ターン、更新理由を記録する。補正が使われた数は、補正なしなら必ず別行動を選んだことを意味しない。候補順位が変わる条件はnative-coreの制御試験で別途確認した。自律方針は対局内とセーブ再開で持続し、新規対局ではリセット。既存の対局間経験学習を廃止・置換しない。

healing-events.csvのR1ActorTurnStartは既存Priestオーラによる回復。既存経路ではsourceLifeIdが空なので、この記録だけで施術者の陣営や個体を確定しない。自然回復とオーラ回復はcallerで区別する。戦闘・回復の仕様自体は今回変更していない。

native-coreはUnityネイティブEditorで59項目と各下位契約、自律方針16項目を実行。native-playmodeは実際に20フレーム以上進めた制御場面で、正規の召喚/住宅建築/資源/AP支払い/市民増加を確認する。これらの一時的な制御場面を自然対戦と混同しない。Tests~のハーネスを検証用Assets/Editorへ配置し、-executeMethod SquadCoreValidation.Run（Editor契約は-quitを追加）またはA1LiveValidation.Runで実行できる。後者は自分でPlay Modeに入り、終了コードを返す。元プロジェクトへ試験コードをコピーして実行しない。

static-compileはRuntime/Editor/Release定義のC#コンパイルであり、実プレイやPlayerビルドの証拠ではない。バッチEditorのFPS/メモリは長時間リーク、製品ビルド性能、プレイ感の証明ではない。認証引数を含み得るUnity生ログは公開せず、テストの固有行のみ抽出した。sha256.jsonは本フォルダの証跡の正確なバイト列。
