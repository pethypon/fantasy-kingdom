各match.jsonのScenarioScopeは通常New Game＋Player開発AI15。EnemyはCombat、脅威度15/35。既存開発AIのゲーム時間制限は無効。資源・AP・HP・軍の追加、思考予算/timeScaleの変更、隠れた敵情報のAIへの供給はしない。R4は既定の無効/shadow。全試行は所有者ターン上限で止めており勝利ではない。同シードでも実時間探索・フレーム順序等に差があるため決定論的な勝率A/Bではない。sourceMatchesCurrentMainは指定した検証元checkoutとの一致であり、当時のGitHub masterとの一致を意味しない。

nation-economy.csvのfacilityCountsは生存する自軍建物をkindまたは独立した作者IDごとに記録する。形式はidentity=count:levelSum。累計建築数と現存数を混同しない。lastObservedArmyもその陣営の最終観測時の数で、終了直後の全盤面数ではない。住宅は市民ストック容量なので、家が無いことだけで増兵不能とはしない。productionPerTurnは支払い予測用の保証生産、予定需要と不足を別列へ記録する。魔石の確率生産を保証収入と扱わない。

actions.csvのSubCrystal建築行は攻撃ではない。攻城集計は成功したAttack/SkillUseだけで絞る。撃破は観測済みの直前HP以上の実HPダメージを与えた事実から判定。未撃破対象はcensored=trueで、撃破時間０とはしない。elapsedRoundsToKillは初攻撃から撃破まで両端を含むゲームラウンド。攻撃していない中断期間も含む。mainCrystalObservedRounds/commanderObservedRoundsで、未発見と発見済みの判断失敗を区別する。

formal-playmode.txtは20実フレーム進行後の制御試験。実在の地形、通常データの駒、正規攻撃候補・実行・実AP支払いを通す。耐久試験はフルHP5000の本番サブクリスタルを用い、各APサイクルで35APを準備し、正規ResetFatigueを呼ぶ。通常の経済・移動・敵の反撃・ターン進行は再現しないため「普通の試合で30ターン勝利した」等の証拠にはならない。過去の試験手順で疲労を持ち越した失敗runは最終証跡に含めない。

core.txtはネイティブEditorの契約試験。static-compileはプレイではない静的C#コンパイル。候補詳細は120000行で打切りとなる場合がある（telemetry-status.json）。集計・実行・スキル・経済記録は継続。候補サンプル数は独立した機会数ではない。
