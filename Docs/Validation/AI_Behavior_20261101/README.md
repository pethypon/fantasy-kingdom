# AI・クリスタル・回復連携の実行証跡（2026-11-01）

Unity 6000.3.8f1の分離プロジェクトで、通常New Game＋開発用Player AIを実行した9試行。3シード、敵脅威度15/35。Player AIは15固定。合計1280ラウンド、2560所有者ターン。全試行は設定した所有者ターン上限で終了し、勝敗未決着。資源・軍・敵情報を試験からAIへ追加していない。timeScaleは1。既存開発AIモードのゲーム時間制限は無効（各match.jsonに記録）であり、通常手動プレイの制限時間・タイムアウト試験ではない。

before=1d3d897、after=ea4b627、final=f013596、release=e687e3c。releaseはfinalと同じゲーム判断・ルールで、開発用の実回復診断イベントを補完した版。各run.jsonに正確なSHA・入力ダイジェスト。最終runtime入力SHA256はb35e522026d247c525fdd0ef8db2cc77aaf5cf581d5067f8d14faf78210c9024、ゲームアセットSHA256はfe434f82ea69ac044e842d85bc8eebbb41eef07ba3235c8ebeaa77eeedb73d82。全実行でアセットは同一。探索の実時間制限・フレーム順序・個体差等があるため、同シードでも決定論的A/Bや勝率改善の証明ではない。

既存作戦・部隊レイヤーは動作している。R4の高次自律プランナーは既定の無効/shadowで、R4MultiStepSquadPlanning=false。新しい高次AIが有効になった試験ではない。

formal-playmode-final.txtは20実フレーム進行後の制御試験。手動で4体作戦を準備し、正式な命令・実AP支払い・回復・全員の移動を確認する。両軍の本番メインクリスタルを500負傷させて自然回復除外を確認する。ダンジョン報酬サイクルの試験は別の制御された所有状態。自律的な編成・回復選択・通常対戦の勝利とは区別する。core-final.txtはネイティブEditor内のコア/契約試験。static-compileは実ゲームを動かさない静的コンパイル。

healing-events.csv/crystal-hp.csvの回復イベントが有効なのはreleaseの2試行だけ。以前のRecordHealは診断イベントを発行していなかったため、旧版の空ファイルは公開対象から除外。75件のユニット回復は全て自然回復で、回復職スキルではない。growth試行のクリスタル3回分の回復はDungeonSystem.BuffCrystalの実呼出しを記録。

operation-orders.csvの選択をactions.csvの実移動成功と陣営・ラウンド・駒・座標で照合。groupedActualMovesは生存部隊3体以上、fourMemberActualMovesは4体での命令成功数。cohesiveは最大XZスパン8以下という分析上の指標で、集団戦闘や包囲成功そのものではない。部隊IDだけで連携成功と評価しない。

decisions.csvは最大120000行で打切り。telemetry-status.jsonに打切り状況、skills.csv等の集計は継続。召喚候補数は独立した機会数ではなく観測サンプル。selectedは候補評価段階で、実選択はchosen列またはactions.csvを見る。actualHealingDoneは建物強化によるHP上昇も含み得るため、回復スキル判定にはSkillUseで絞る。

CSVのObjectiveAttacksは勝利対象専用ではない。勝利対象はVictoryObjectiveAttacksおよび実際の司令官/メインクリスタルIDで区別する。観測用テレメトリは全盤面を記録するが、AIへ入力しない。隠れた敵情報を許可した試験ではない。

画像は記録時のプレイヤー視点。Fogで敵が見えないため敵の集団行動の証拠は命令と実行ログで照合する。バッチEditorのフレーム/メモリは診断を含む値で、製品ビルドのFPSや長時間リーク解消の証明ではない。Editor生ログは認証引数を含み得るため公開しない。

sha256.jsonはこのフォルダ内の証跡バイト列。analyze-original-runs.pyは元workディレクトリ配置の集計スクリプト。検証用Tests~は通常製品ビルドに含まれない。
