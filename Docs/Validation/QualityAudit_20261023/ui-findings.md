# UI 実行調査と修正記録 — 2026-10-23

## 検証方法と限界

既存の Unity ゲームを起動した試合で、実際の `Button.onClick`、選択パネル、召喚行の `OnPointerEnter` を実行した。ゲームカメラと本番 Canvas を RenderTexture に描画し、1280×720 と 960×600 の PNG を保存した。HTML の再現画像やモックではない。試合中の駒の数値・費用・位置・視界はこの UI 調査のために書き換えていない。

ただし、物理マウスでの操作、初見の人による理解度、画面の実コントラスト、色覚差、長時間操作の疲労は未検証。RT 出力寸法の変更はウインドウの手動リサイズとは異なる。本項の「見やすさ」は保存したネイティブ画面を読んだ評価であり、ユーザーテストの成功率ではない。

初回記録は [`ui-before/ui-observations.json`](ui-before/ui-observations.json)、方法は [`ui-before/ui-method.txt`](ui-before/ui-method.txt)。初回は 16 画像。最終の再実行は [`verified-ui/ui/ui-observations.json`](verified-ui/ui/ui-observations.json) と 22 画像を保存し、Unity 実行は exit 0 で終了した。両解像度の冷状態 hover と再表示の回帰検査が PASS。敵が実際の視界内にいない場合、敵の選択を未検証として記録した。既存の味方建物がない場合も同様。頭上 UI は後述の RT 変換の影響を完全には除けず、この監査では製品の欠陥とも成功とも判定していない。

文字数は TMP のレイアウト情報から取得した画面内グリフ中心の概数。背面の暗い HUD やモーダルに隠れたラベルを完全には除外していない。テキスト面積の合計は重なりを重複加算するため、盤面の遮蔽率として使わない。`isTextOverflowing` は「修正候補」の抽出であり、そのまま不具合数に数えない。

## 確認した問題と対応

### UI-01: 説明書が小さく、本文のレイアウト高さが内容に一致しない

- **証拠**: [`ui/10-manual-pieces-1280x720.png`](ui-before/10-manual-pieces-1280x720.png)、[`ui/10-manual-pieces-960x600.png`](ui-before/10-manual-pieces-960x600.png)。初回 TMP 記録では本文は 16 論理 px、960×600 時の推定文字サイズは 8.43 px。105 行の本文の `preferredHeight` は 2368.20 論理 px に対し、実際の本文矩形は高さ 10.54 出力 px。1280×720 でも本文は約 10.67 px。
- **再現**: 試合中の「メニュー」→「駒・ルール説明書」→「駒」。両 RT 解像度で再現した。
- **頻度**: 2/2 解像度。スクロールで最下部まで実際に到達できるかは初回では操作しておらず、その部分は未検証。
- **原因推定**: 親 `ContentSizeFitter` と全面 stretch の子 TMP の組み合わせで、本文の希望高さがスクロール内容へ正しく伝達されない。固定 16 px も小さい。
- **修正**: 本文 26 論理 px、共通日本語フォント、高さを内容に合わせる VerticalLayoutGroup、明示的なスクロールバー、タブ切替時の先頭復帰。文字やルールそのものは削除していない。
- **副作用**: 一画面に入る情報量は減り、スクロール量が増える。引き換えに各行を読める大きさに保つ。後続の実行ではルール本文の先頭と最下部を別画像で確認する。
- **修正後**: [`verified-ui/ui/10-manual-pieces-1280x720.png`](verified-ui/ui/10-manual-pieces-1280x720.png) と [`verified-ui/ui/10-manual-pieces-960x600.png`](verified-ui/ui/10-manual-pieces-960x600.png) で本文拡大と正常な高さを確認。本文は 1280 で約 17.33 px、960 で約 13.70 px。両方とも 105 行の内容高は 3973.04 論理 px、viewport は約 639 / 674 論理 px。[`verified-ui/ui/12-manual-rules-bottom-960x600.png`](verified-ui/ui/12-manual-rules-bottom-960x600.png) では最終の「固定スキル」の文章が実際に表示され、スクロール位置は両解像度とも誤差 ±0.000002 以内で末尾の 0 を確認した。途中の監査にあったタブ引継ぎ・RT 切替後の位置ずれはテスト側で修正済み。

### UI-02: 説明書のタブ・閉じるボタンだけ外観が異なる

- **証拠**: UI-01 と同じ実行画像。緑の四角いタブと灰色の閉じるボタンが、ゲーム中の金属・木枠ボタンと一致していない。閉じるボタンは親の横幅を使わず、表示文字も小さい。
- **再現・頻度**: 説明書を開く。両解像度 2/2。
- **原因推定**: 共通 UIFactory を使わない独自の Image/Button/TMP 生成と、閉じるボタンの stretch 未設定。
- **修正**: 共通テーマのボタン生成と 24 論理 px のラベルを使用し、閉じるボタンを行全体に配置。
- **副作用**: 既存のテーマ設定に追従する。機能・タブ数・クリック数は変わらない。
- **修正後**: [`verified-ui/ui/10-manual-pieces-1280x720.png`](verified-ui/ui/10-manual-pieces-1280x720.png)、[`verified-ui/ui/11-manual-rules-960x600.png`](verified-ui/ui/11-manual-rules-960x600.png) で金属ボタンへの統一、閉じるボタンの正常な横幅とラベル拡大を確認。

### UI-03: 選択パネルでスキル名が重複する

- **証拠**: [`ui/02-ally-selected-1280x720.png`](ui-before/02-ally-selected-1280x720.png)、[`ui/02-ally-selected-960x600.png`](ui-before/02-ally-selected-960x600.png)。中央の「前方突破」と右のスキルボタン「前方突破」が重複している。
- **再現・頻度**: 固有アクティブスキルのある味方を選択。今回の騎士選択で 2/2 解像度。全職種の全状態を実行したわけではない。
- **原因推定**: 固有スキル名を中央ラベルと実行ボタンの双方へ常に代入している。
- **修正**: スキル実行ボタンに名称がある場合だけ中央の同名を省略。敵や確認専用の表示では中央の名称を残す。
- **副作用**: 味方選択時の中央欄に空きができる。スキル情報や使用 AP はボタン・詳細に残る。
- **修正後**: [`verified-ui/ui/02-ally-selected-960x600.png`](verified-ui/ui/02-ally-selected-960x600.png) で中央の「前方突破」が消え、右のスキル名・AP は維持されている。1280 でも同様。測定グリフ数は 145→141（頭上 UI を正しく写す前の比較）。

### UI-04: 召喚行の維持費で「水」と数値が分断される

- **証拠**: [`ui/07-summon-list-1280x720.png`](ui-before/07-summon-list-1280x720.png)、[`ui/07-summon-list-960x600.png`](ui-before/07-summon-list-960x600.png)。魔法使いの維持費末尾が「水」→次行「1」になっている。
- **再現・頻度**: 「ユニット召喚」一覧の魔法使いの行。2/2 解像度。資源が多い行全般の発生率は未測定。
- **原因推定**: 長い「維持（Lv1）」接頭語と複数資源を同じ細い行に記載し、末尾が文字単位で折り返される。
- **修正**: 接頭語を「維持/T」に短縮。維持費の全資源・数値を維持し、Lv1 の意味は制作前の詳細表示に残す。
- **副作用**: `/T` が毎ターンの意味であることに初見説明が必要な可能性はある。ツールチップでは「維持費 / 毎ターン」と明記する。人による理解度は未検証。
- **修正後**: [`verified-ui/ui/07-summon-list-960x600.png`](verified-ui/ui/07-summon-list-960x600.png) の魔法使いで「水1」が同じ行に入り、独立した「1」の行が消えた。資材・費用を削除していない。

### UI-05: 詳細パネル本文が小解像度では小さい

- **証拠**: [`ui/03-ally-details-960x600.png`](ui-before/03-ally-details-960x600.png)。TMP の記録では本文 22 論理 px、出力上の推定値は 11.60 px。
- **再現・頻度**: 味方選択→「詳細」。960×600 で 1/1。1280×720 は約 14.67 px。
- **修正**: 確認専用の本文を 26 論理 px に拡大。既存のスクロール領域を使用し、能力内容を削除しない。
- **副作用**: 長文でスクロールが増える。戦闘中の常時表示パネルには影響しない。
- **修正後**: [`verified-ui/ui/03-ally-details-960x600.png`](verified-ui/ui/03-ally-details-960x600.png) で拡大を確認。TMP の推定値は約 11.60→13.70 px。長文は既存のスクロール内に残り、常時表示の選択パネルの大きさは変わらない。

### UI-06: 説明書の勝利条件の記載が実装と一致しない

- **証拠区分**: 初回の実画面は「駒」タブのみ。`GameManualUI.BuildRulesText()` のコードではクリスタル破壊のみと記載される一方、`MatchObjectiveRules.IsDecisive` は王またはメインクリスタルを判定する。初回段階ではルールタブの実画面は未検証。
- **再現**: 「メニュー」→「駒・ルール説明書」→「ルール」。後続の監査に実行・撮影を追加した。
- **原因推定**: 独立した古い説明文の更新漏れ。
- **修正**: 王またはメインクリスタルのどちらかを撃破すると勝利、自軍が失うと敗北、サブクリスタルは敗北条件から除外と明記。ゲーム判定自体は変更しない。
- **副作用**: 説明が数十字増えるが、重要な勝敗条件を正しく伝える。
- **修正後**: [`verified-ui/ui/11-manual-rules-960x600.png`](verified-ui/ui/11-manual-rules-960x600.png) の基本ルール冒頭で「相手の王、またはメインクリスタル」「自軍の王、またはメインクリスタル」「サブクリスタルは敗北条件に含みません」を実画面で確認した。

### UI-07: 最初の召喚 hover だけ背景が本文より短い

- **証拠**: [`ui-first-hover-before/08-summon-hover-1280x720.png`](ui-first-hover-before/08-summon-hover-1280x720.png) の修正前中間記録では、黒い背景は上部約 100 論理 px のみで、スキル・維持費・アビリティ文が背景外へ出ていた。一度表示した後の 960 の hover は正常であった。初回の「全く出ていない」監査失敗とは別の問題。
- **再現・頻度**: 新しく作成した共有ポップアップの最初の hover。中間実行の cold 1280 で 1/1、warm 960 では 0/1。全職種での再現率は未測定。
- **原因推定**: `Show()` が最初にポップアップを非表示にし、その非表示階層へ新しい TMP を作ってから、TMP の初期化前に希望高さを測っていた。2 回目からは初期化済みのためサイズが異なった。
- **修正**: 同じ実データを代入した後、ポップアップを有効化してから `ForceMeshUpdate(true)` と高さ測定を行う。スクロール・非表示時のクローズ処理は維持。フォントやゲーム値は変更しない。
- **副作用**: 初回 hover で同期的な TMP メッシュ更新が 1 回増える。常時 Update や行ごとの新しい更新処理は追加していない。
- **回帰検証**: 各解像度で監査専用ポップアップを破棄し、冷状態から最初の実 hover を実行。本文の非 overflow と希望高さ以上の領域を確認し、再表示の高さが初回と一致することを検査した。1280 / 960 の 2/2 で PASS。初回・再表示の背景高はいずれも 549.28 論理 px、本文高・希望本文高はいずれも 521.28 論理 px。[`verified-ui/ui/08-summon-hover-1280x720.png`](verified-ui/ui/08-summon-hover-1280x720.png) でスキル・アビリティまで黒い背景内に収まる実描画を確認した。

## 製品の不具合と判断しなかったもの

- **初回 hover 画像にポップアップがない**: [`ui/08-summon-hover-1280x720.png`](ui-before/08-summon-hover-1280x720.png) は一覧と同じ 278 グリフだった。キャプチャのための Canvas/RT 切替が ScrollRect の変更通知を発生させ、ポップアップを閉じる本番処理を呼んだ可能性がある。監査側を「RT とスクロールを安定させた後、本物の PointerEnter を実行して撮影」へ修正した。これをゲーム内で hover が常に壊れる証拠にはしない。
- **TMP overflow 候補**: AP ラベル、Lv、攻撃ボタンがフラグに上がったが、実画像では値や文字は読めている。フラグを一律にクリッピングバグとして扱わない。
- **頭上 HP/バリアの不在や位置**: このキャプチャは本番 Overlay をカメラ Canvas へ一時変換する。頭上表示の LateUpdate が画面ピクセル座標をそのまま world position へ設定するため、変換中の座標に影響があった。監査側で座標変換と復元を行ったが、最終 960 の画像でも一部の表示が上部 HUD 付近に残る。したがって、この RT 画像で頭上 UI の正確な位置・密集状態を評価したとは報告しない。本番 Overlay を変換せずに撮る別経路での確認が必要。
- **「ナイト」と召喚一覧「騎士」の名称差**: 両方は実画面で確認できた。役割情報を混同しやすいため名称の統一を提案するが、既存の呼称の選択をこの調査だけで変更していない。
