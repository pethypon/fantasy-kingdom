# 18職種：実行データと限定戦闘比較（2026-10-23）

## 実行したもの／未検証のもの

- Unity 6000.3.8f1 の本番 SampleScene を開始後、実際の `UnitSetting.UnitDataMap` を参照。18職種×4レベル、計72行を出力した。
- 追加の隔離ランタイム試験：同レベルLv1/Lv10で1,296ケース＋異レベル72ケース＝計1,368ケース、実際の通常ダメージ処理9,618パケット。10ラウンド上限、共有ルール最大AP60。上限引分0件。最新出力は`verified-ui/roles/`。
- これは**通常ダメージ交換のストレス試験**。射程・合法な攻撃マス・移動・戦術・スキル・弾倉・XP・自然回復・バリア回復・自動反動を再現した実戦対戦ではない。魔法狙撃手の反動を除いているため、その交換成績を本来の強さと読まない。
- 侍の通常命中ゲージ通知とHP適用内部の反撃は生存結果に反映される。ダメージ集計は起点の通常攻撃パケットのみで、反撃ダメージを各側に足していない。
- 先手・後手を入れ替えているが、同じ組合せの左右反転も含まれる。独立した1,296試合の勝率ではない。
- 実行前後の既存駒HP・最大HP・バリア・ATK・レベル・疲労・位置と両国家JSON不変を確認：`LiveActorHealthAndEconomyUnchanged=true`。乱数状態も復元。
- 実際のAI対戦は別の`threat-1`、`threat-30`および既存シード161803/271828記録で評価する。同職種の低Lv対高Lvを隔離ランタイムで比較済み（下記）。少数精鋭対大軍の対照実戦は**未検証**。

## 要注意の差分（数値は変更していない）

### P2：ガーディアンの「高HPで耐える」と初期実効耐久の違い

- **分類**：実データで確認した設定差。確定不具合やバランス崩壊とは判定していない。
- **証拠**：`verified-ui/roles/roles.csv`のナイトLv1/Lv10（CSV行2/3）、ガーディアンLv1/Lv10（行26/27）。
- **再現手順**：本番SampleSceneから新規ゲームを開始し、`RoleBalanceAudit.Run(systems, output)`を実行。該当2職種のLv1/Lv10行のHP・バリア・ATKを比較する。
- **発生頻度**：同一本番定義なら毎回この設定値になる。劣位・過剰性能が実戦で起こる頻度は未測定であり、このデータだけで算定しない。
- **実測データ**：Lv1ガーディアンHP42＋バリア15＝57、ナイトHP32＋バリア70＝102。Lv10はガーディアン177＋33＝210、ナイト86＋88＝174。HP・ATKの伸びが大きく、初期と育成後で相対的な耐久・火力が変わる。
- **原因の推定**：既存の職種別HP/ATK成長と、今回のバリア初期値・共通+2成長の組合せ。単純にバリア15だけの設定不良とは断定しない。
- **改善案**：生命接続あり/なし、Lv1/10、HPを直接失う代償を受ける場面、回復支援あり/なしを比較する。高HPの独自価値が機能するか見てから調整する。
- **副作用**：初期HPを一律増加すると育成成長・生命接続・回復割合の強さも変わり得る。根拠なく数値を変更しない。

### P2：航海士とガーディアンの共通レシピ・人口コスト

- **分類**：実データで確認したレシピ差。人口0は仕様の可能性があり、確定不具合とは扱わない。
- **証拠**：`verified-ui/roles/roles.csv`のガーディアンLv1（CSV行26）と航海士Lv1（行62）の`cost_citizen=0`、同ファイルの他16種は1。
- **再現手順**：上記ランタイム監査を実行し、ガーディアン・航海士の`cost_*`と`upkeep_*`を確認。両者の維持費は市民0だが、木1・石4・鉄1・魔1・水1・パン1/ターンを要するため、人口不要を無償運用と誤解しない。
- **発生頻度**：両職種の同定義を使用する場合の固定レシピ。人口制約を外したことによる過剰編成や経済破綻の発生頻度は実戦未測定。
- **実測データ**：両者HP42/ATK14、石50・魔30・水50・AP10、市民コスト0。航海士の初期バリア30はガーディアン15より高い。
- **解釈**：生命接続と正面攻撃＋引寄せの役割が違うため、これだけで上位互換としない。一方、市民0は他16種の市民1と違うため、人口に拘束されない高価な編成が意図どおりか確認する価値がある。
- **改善案**：同じ資源・AP予算で支援対象の救命率と接敵時火力を比較。人口0が意図された仕様ならUIにも明確に出す。
- **副作用**：勝手に市民1へ変更すると既存国家・召喚可能数を変えるので、今回は変更しない。

### P1/P2：重戦士の実戦スキルは未確認／竜騎士は最新再戦で確認

- **以前の観測**：脅威度1/30の実戦`run.json`では`HeavySkills=0`、`BypassHits=0`。18種表では重戦士14AP、竜騎士16AP、通常攻撃は疲労0で2AP。有効フラグはtrue、設定エラーなし。
- **最新再戦の実測**：`protected-retest/01-271828/match.json`は重戦士12個体・竜騎士28個体を観測し、`HeavySkills=0`、`BypassHits=2`。
- **竜騎士の証拠**：同`actions.csv`のCSV行2112はPlayer/T110/id1042の`SkillUse:Infantry:special18`、HPダメージ16・撃破1。行2813はEnemy/T137/id1404の同スキル、HPダメージ21・撃破1。`UnitSpecialSkill`の18はDragonKnightPierce。実際に両陣営のAIが竜槍貫通を選び、各1回撃破したことを確認できる。
- **解釈**：竜騎士を「AIが使わない」と一括評価しない。2件だけでは選択頻度の妥当性や他の合法機会を逃していないかは不明。重戦士は生成されても専用スキル発動0で、対象のバリア量・隣接・残AP・通常攻撃との評価差を追う必要がある。単に倍率を増やす根拠にはならない。
- **次の改善**：専用技の合法候補数と選択率を記録し、可視の高バリア目標に隣接して14AP以上を残した重戦士で比較する。竜騎士はゲージ充填後に有効な対象があるか、通常攻撃で確殺できるかを分けて確認する。
- **副作用**：専用技への固定加点は過剰消費や、通常攻撃で倒せる敵への無駄打ちを生む。通常攻撃とのAP効率・撃破価値・有限バリア温存を分けて比較する。

### P2：高レベル維持費と少数精鋭

- **実測データ**：共通の鉄・水・パンはLv1各1、Lv10各2、Lv50各6、Lv100各11/ターン。木・石の職種差も増加し、Lv100ガーディアン/航海士の石は44、クロスボウの木は44、スカウトの木・石は各22/ターン。魔法狙撃手の魔維持費はLv1で3、Lv100で33。
- **未検証**：Lv100軍の実際の維持可能規模、経済崩壊からの復帰、Lv10一体とLv1三体の実戦価値は測っていない。通常ダメージ表だけでは精鋭と大軍の優劣を判定しない。
- **改善案**：共有AP60・等しい制作費・同じ生産基盤の三条件を別々に固定して比較する。多数軍は疲労分散・接敵面積、精鋭はレベル維持費・割合回復という異なる利点があるため、条件を混ぜない。

## 異レベルの追加実測：18職種、同職種Lv1対Lv10

- **手法**：18種×左右のレベル入替×両先手＝72ケース。双方の自軍ターンに最大AP60を与える通常ダメージ交換。移動・射程・スキル・反動・回復等を除外するため、実戦のレベル差勝率ではない。同条件の左右反転を含む。
- **結果**：Lv10側の生存66ケース、Lv1側の生存6ケース、打切り・引分0。全72ケースが試験ラウンド1で終了した。
- **低レベル先手の36ケース**：すべてでバリア損失が発生。30ケースではHP損失にも到達した。HP＋バリアの起点通常パケット損失は27～126。ナイト・プリースト・白魔導士では先手でもHPへ届かずバリアだけを削った。これはダメージ無効ではなく有限バリアへの有効な損失。
- **低レベルが生存したケース**：アサシン、忍者、魔法狙撃手が先手のとき（各左右反転2ケース）。先手の一勢力が60APを連続使用できる条件であり、反撃可能な軍配置や交互行動の比較ではない。特に魔法狙撃手の自動反動を省略しているので、実戦の低Lv狙撃手が同じ結果になるとは言えない。
- **解釈**：レベル差があっても通常攻撃はバリア、場合によりHPを削ることを実処理で確認した。一方、先手で脆い高Lv兵を倒せる例は、成長がHPよりATKへ偏る職種と一括AP消費の組合せを示す。単に「Lv10が強すぎる」「Lv1が強すぎる」と結論しない。
- **次の比較**：同じ制作・維持予算の軍、合法な射程・接近・反動を含めた配置戦で、低Lvが何を失い何を達成できるか測る。今回の試験だけでは少数精鋭対大軍や逆転手段を評価できない。
- **証拠**：`verified-ui/roles/normal_mixed_level_summary.csv`、同`normal_mixed_level_packets.csv`、`role_audit_metadata.json`の`MixedLevelExchanges=72`。
