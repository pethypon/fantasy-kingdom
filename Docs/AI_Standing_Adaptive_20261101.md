# 常備軍・回復/偵察支援・市民成長・自律方針の改修（2026-11-01）

## 結果と範囲

初期3駒で止まる原因を、編成計画・召喚の支払判断・生産投資の3箇所で修正した。通常対戦の最終3試合では、30ラウンド時点の軍はプレイヤー/敵の全6側で6体。60ラウンドまでに最大7～13体、回復役1～3体、住宅1～2軒、市民最大8～11人を確認。最終3試合の途中を含め、維持費未払い・実行エラー・例外は0だった。

各60ラウンドで試験打切り。勝利までの完走や、学習による勝率向上を実証したとはしない。全18職の戦闘能力は変更せず、費用と維持費だけ調整した。主指揮官を軍の数に含めない。

## 初期3駒・支援不足の原因と変更

1. 初期編成は戦闘員2体＋斥候1体。旧回復役要求は「戦闘員3体以上、かつ負傷者か遠征あり」なので、無傷の初期軍には回復役を要求しなかった。6ターン目から無傷でも回復役を準備する。実際の回復能力を持つ定義を選び、兵種名だけで回復役とみなさない。
2. 短期の購入リストが3件の戦闘員で埋まると支援要求が入らなかった。回復/偵察の不足を先に予約し、作戦側の要求とは二重計上しない。戦闘員約4体に回復役1体、常備回復役の目標上限3体。作戦固有の要求は既存経路を保つ。
3. 経済回復モードでは、実際に養える予定兵まで通常優先度から外れていた。最低限の戦闘員・最初の回復役・失った斥候は、正規の支払/維持/入力予測に通る場合に優先する。共通AP、召喚可能マス、資源支払い、維持費を免除しない。
4. 未来の建築計画をすべて貯金するための残高が、補充の必須残高にも加算されていた。資金のある常備軍補充では、現在の義務・設定した実用予備・保証収入を使う。市民は設定の自由予備2人を残す。無関係な建築予定を理由に補充を無期限に止めない。

戦闘員の最低目標4体を6ターン目から準備。中長期には15ターンごとに増やし、戦闘員目標16体まで。これは全軍の絶対上限や無料生成ではなく、支援/偵察を別にした不足計画である。資金不足なら待ち、その理由を既存の診断へ残す。

## 市民と住宅

市民が5人で止まるのは、基礎容量5と、住宅需要を「1体1行動のAP」「直近の購入1回」だけで見ていたため。現在は疲労を含む継続攻撃と、同じターンの実際の増援1回のAPも準備する。遠いAP目標を丸ごと破棄せず、実際に回復可能な市民数まで段階的に準備する。

12ターン目から市民予備8人も目標にする。住宅は容量を増やし、市民自体は通常の経済ターンで増える。食料と維持の予測に通らなければ建てない。標準住宅は木55/石55/水10/AP5、容量+3。Lv2/Lv3の容量は+5/+8。独自の住宅定義はその作者データを使う。

## 経済データ

レベル/経験値の廃止と戦闘基礎値1.75倍は維持。維持費倍率は互換用既定値5を残し、本番Rules.assetを2へ設定、全軍への共通追加維持費を0にした。18職種を役割に応じた作者維持費と制作費へ再設定した。18資産すべて、制作費/維持費以外のシリアライズ値が開始masterと一致することを検査した。

初期3軍の毎ターン維持費は、木20/石25/鉄15/パン15/水15から、木2/石0/鉄4/パン6/水2へ変更。市民のパン消費は別に払う。初期備蓄は両陣営とも木140/石140/鉄60/魔石12/パン100/水80/市民5。クリスタルの減衰する序盤支援は10ターン。継続的な無条件収入を追加したわけではない。

Priestは制作の魔石8、維持はパン2/水2。回復役を準備するだけで序盤の恒久魔石生産を必須にしない。他の魔法職の維持費は別で残す。標準鉱山は木30/石30/水15/市民1/AP5、鉄生産4/7/11。Lv2/3の保証魔石は1/2、確率ボーナスは別に計算。木材/採石は8/12/17、水は6/10/15、小麦とパンは5/8/12。生産入力や施設維持費も支払う。

初期の木石投資と鉄生産の接続が悪い試行、支援生産が29～36ターンまで遅れる試行を実際に確認して調整した。資金を強く固定した途中版は基礎設備を止めたため撤回した。失敗試行も証跡のall-trial-summary.jsonに残し、最終版の成果として数えない。全職種/施設の解決済み費用と生産量は各economy-definitions.jsonに収録。

## AI自身による判断方針の調整

`AIAdaptiveDecisionPolicy`を既存の自己評価と統合した。探索・進軍・対部隊戦闘・攻城・支援・補充・経済の7種類について、実行結果のターン平均を更新する。脅威度10以上、最低3試行ターン、更新率0.25、点数補正最大±18。大量の行動1回で方針を支配しないよう、1分類64件/ターンまでを平均する。

既知の目標がある健全な軍が3ターン進捗を作れない場合、通常の投資より探索/進軍を重くする。既存の観測に由来する安全な進軍候補だけ、通常優先度4から3へ上げられる。生存/緊急防衛/確実な決着/支払い等の上位段階には入れない。王はこの補正から除外。AP、視界、ダメージ、召喚/建築ルール、相手の隠れた位置を変更・取得しない。

7要素の固定長状態で、行動履歴やUnityオブジェクトを追加保持しない。対局内とセーブ再開で継続し、新規対局では状況固有の重みを初期化する。既存の対局間経験学習は存続。NaN/異常値・旧セーブ・無効設定・陣営間分離・途中セーブ・実行反映を制御テストで確認した。点数補正が付いた行動数は、補正なしなら必ず別行動だった回数ではない。

## 変更箇所と編集場所

- `AIStrategicGovernor.Recruitment.cs`、`.Development.cs`、`AIStrategicGovernor.cs`：支援を含む常備編成、支払可能な補充の優先、軍備目標。
- `AIBasicResourceEconomy.cs`：現在の義務と将来投資を分け、資金のある最低限の補充を停止しない。
- `AIStrategicGovernor.Housing.cs`、`AIHousingConfig.cs`、`HousingConfig.asset`：継続攻撃/増援AP、市民予備、段階的な住宅準備。
- `Reflection/AIAdaptiveDecisionPolicy.cs`、既存Reflection、`AICommander.cs`：固定長の方針状態、結果更新、保存/再開、通常候補への反映。
- `GameAuthoringRules`、`FixedUnitRules`、本番Rules・18職種・6生産施設・標準住宅：維持/制作/生産費用の設定統一。
- 開発スタジオと説明文：維持費を固定の「5倍」と誤表示せず、設定倍率を示す。
- `Tests~/AIStandingArmyTests.cs`、`AIAdaptivePolicyTests.cs`、住宅/経済/固定維持費テスト：両陣営の実支払、実生成、住宅後の市民増加、方針の契約。

Unityでの調整は`Fantasy Kingdom > 開発スタジオ（日本語）`のゲームルール、職種、建物設定から行える。維持費倍率は「維持・経済」。常備軍・回復/偵察・市民予備は`Assets/Resources/AI/HousingConfig.asset`、自律方針の有効化/脅威度/速度/補正上限は`Assets/Resources/AI/ReflectionConfig.asset`をInspectorで編集できる。新項目は日本語ラベル。独自職種/建物は削除しない。

## 検証と残る範囲

Unity 6000.3.8f1の実行環境で、Editor契約59項目（下位契約含む）、自律方針16項目、両陣営の住宅/維持/経済/常備編成のPlay Mode契約が合格。健康な軍の回復役を正規に選択/支払/生成し、斥候の不足要求、住宅建築後の実市民増加まで確認した。Runtime/Editor/Release定義の静的コンパイルも成功。静的コンパイルを実プレイとは扱わない。

自然対戦は上表の3条件。開発プレイヤーAI15、敵Combatの脅威度15/35、異なる地形シード、初期データ/共通ルールのまま。60ラウンド以内の未払い0は確認したが、全18職の対面勝率、数時間対戦、製品ビルド性能、決着までのバランスは未検証。高脅威度の一側では20ラウンド時点の現存軍は3/回復役0だったが、初生産11ターンと後続補充を記録している。生存数の一瞬だけで「生産していない」とは判断しない。

記録と再現条件は[検証資料](Validation/AI_Standing_Adaptive_20261101/README.md)。コード解析の推定と、自然対戦/制御試験を区別した。
