# 脅威度10以降の複数ターン作戦・確率推定（2026-10-02）

## 適用範囲

今回の7項目は `AIAdvancedStrategy` と `PlayerResponseModel` を入口に、脅威度10以上だけで使用する。1〜9の既存の判断段階は維持する。合法な候補へ補正を加え、実行直前のAP・資源・移動・建築ルールを迂回しない。

## 1. 複数ターン作戦（最優先）

`AIPlan` が目的、観測済み目標、必要な駒、段階、成功・中止条件、開始ターン、期限を保持する。`AIPlanManager` は一つの作戦を複数ターン維持し、担当駒を継続して割り当てる。

- 陽動: Scoutの示威 → 新しく寄ってきた敵2体を視認 → Assassin・Knightを反対側へ迂回 → 観測済み拠点への攻撃 → 帰還。
- 経済破壊: 視認済みBakeryへ迂回 → 排除を確認 → 2ターンの供給影響を推定 → 本隊攻撃 → 帰還。相手の隠れたBread残量は読まない。
- 待ち伏せ: Scoutと遠距離支援2体を用意 → 支援が届く位置で示威 → 追ってきた敵を視認 → その敵を攻撃目標へ変更 → 攻撃成功後に撤退。
- 偵察、弱ったKing、Crystalへの攻勢も目標候補に含む。
- 自陣の危機、戦力半減、情報の失効、必要部隊・反応の不足、8〜9ターンの期限で中止する。危険な示威移動は減点し、瀕死のScoutを囮へ割り当てない。

`EasternFeint` は名称上「東部」だが、実際の示威・本命方向は敵目標への進行方向に対する左右で決める。常に地図の東側へ出す固定作戦ではない。

作戦はゲームセーブにも保存する。ロードではUnityの個体IDを引き継がず、視認した種類・位置から目標を再確認する。反応待ちで保存した作戦は示威から確認し直す。旧セーブに作戦がなくても読み込める。

## 2. 存在確率マップ

`AIBeliefMap` は最後に観測した種類・向き・位置・攻撃力と、公知の移動パターンから存在確率を広げる。Scout・AssassinはKnightより不確実性が広がる。現在見えていて当該個体がいないセルを除外し、欠落・古い情報は「位置不明」の確率として残す。

Scoutには、移動先の視界に入る存在確率に応じた情報収集加点を与える。存在確率は攻撃対象の生成には使わず、索敵先と移動危険度に使う。未観測地形の通行可否や、視界外の実Transform・現在HPは推定に使わない。

これは移動回数や向き変更を近似した有限の確率モデルで、真の確率を保証するものではない。追跡は最大24体、1体256セル、拡散4段階、観測から6ターンまで。省略した確率は位置不明へ移す。

## 3. PlayerProfilerを先読みへ接続

`PlayerResponseModel` が攻撃性・序盤Rush・防衛・側面・経済・スキル・射程・低HP撤退をシミュレーションの応答順位と確率へ反映する。既存PlayerProfilerの視界制限された集計と、軽量なターン観測の集計を統合する。

低HP撤退・スキル・側面・防衛の4比率を `AIPlayerModel.v1.json` に追加した。旧形式の欠落値は0から開始し、座標や個体を対戦間のモデルへ追加保存しない。連続して視認したターンだけを行動傾向のサンプルにする。観測ゼロでは従来のMinimax、少数なら最悪応答を重視し、信頼度が増すほど推定応答を反映する。

確率を使う探索では、通常のAlpha-Beta境界が成立しないため、その枝刈り・境界キャッシュを使わない。候補数・時間上限・時間分割・完了した深さへのフォールバックは維持する。

## 4. 罠・陽動の情報制限

作戦成功の反応は視認した生存ユニットで判定する。視界外の接近や、新たに見えた固定施設を反応した駒として数えない。待ち伏せは支援駒の準備を確認する。敵が引っかからなければ中止するため、プレイヤーが誘導を避ける余地がある。

## 5. 経済投資

`AIInvestmentPlanner` が自軍の在庫・施設の正味生産・必要部隊の召喚費を使い、5ターン先の不足と施設の回収ターンを推定する。原材料のない加工施設を減点し、Bread計画にはField・Wellの上流投資も加点する。

回収値は資源価値とAPの換算を使う目安で、全資源が同一物へ交換できるという意味ではない。残り試合ターンは戦況から4〜24ターン程度で推定し、遅い投資より即応を選びやすくする。既存の不足対応・建築候補とも同じ評価集合で比較する。

## 6. 戦術モチーフとUnityでの調整場所

`Assets/Resources/AI/AITacticalPatternSettings.asset` をProjectウィンドウで選択して、InspectorのRulesを編集する。

- Motif: 孤立した敵への挟撃、孤立PriestへのAssassin攻撃、3体以上への範囲攻撃、弱ったKing、弱く孤立したCrystal、味方支援圏への撤退。
- Minimum Threat: 適用を始める脅威度（最低10）。
- Weight: 加点の強さ（0〜60）。

初期設定は意味のある6種類。配列の最初の300ルールまで評価し、合計加点は65で制限する。重複ルールを大量に作って強さを見せる構成にはしていない。新しい条件の種類は `AITacticalMotif` と認識処理に追加できる。設定の読み込みはCommander生成時に一度なので、変更は次の対戦から反映する。

## 7. 不確実性の扱い

移動先の危険度に、存在確率×観測時攻撃力と、複数の敵が重なった場合の危険を反映する。Priest・低HP駒には大きい露出減点を与える。高脅威度ほど最悪ケースの比率を上げるが、観測の薄いプレイヤーモデルも過信しない。存在確率を真の敵位置として扱わない。

## 保守・負荷・検証

作戦、確率、投資、戦術、応答モデルを別クラスへ分離した。確率は同じ観測情報なら再利用し、危険度はセルごとにキャッシュする。候補評価も16件ごとに処理を返す。これらはCPU側の改善で、GPU負荷や全ゲームのFPS向上率は測定していない。確率の再構築や既存スナップショット生成を含む全フレームを、必ず3ms以内にする保証ではない。

Unity 6000.3.8f1の独立した検証コピーでコンパイル、Play Mode回帰、通常・タイマー・例外によるターン復帰を確認する。具体的な項目数・測定値は `Tests~/AIAdvancedStrategyResults.txt`。テストソースは `Tests~/AIAdvancedStrategyTests.cs`、実行入口は `Tests~/SceneSmoke.cs` と `Tests~/TurnCycleRunner.cs`。Tests~はUnityの通常インポート対象から外れているため、検証コピーのAssets/Editorへ配置して実行する。

実戦の勝率や「人間並み・人間以上」という強さは未検証。作戦は全軍を強制拘束する命令ではなく、観測と安全性で変えられる評価方針として実装した。長距離の迂回には既存の合法移動候補を使い、専用の全経路作戦探索は行わない。
